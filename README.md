# 一刻 · Yike

一刻是本地使用的专注与习惯工具，面向工作、学习和日常习惯。打开即可开始一段专注，为今天的习惯打卡，再通过回顾了解时间花在了哪里、习惯如何积累。应用使用 Flutter 开发，支持 Android 和 iOS。

专注、打卡、回顾构成三个主要页面。机械、水位、日影三套主题提供不同的计时器观感，声音、触感、提醒和应用外组件让计时与记录融入日常使用。

## 专注、打卡与回顾

### 专注：选择适合任务的计时方式

- **番茄钟**：按专注、短休和长休组织节奏，自行设置时长与长休间隔，到点后由你决定下一步。
- **正计时与计圈**：从零累计用时，适合没有预设时长的任务；在计圈面板记录分段，并查看单圈、累计及最快 / 平均 / 最慢等会话内统计。
- **倒计时**：选择常用时长后开始，也可在开始前拨动表盘调整本次目标，结束后按相同时长再计。

三个模式可以同时运行，各自暂停和继续；切换页面或查看模式不会结束其他计时。番茄钟与倒计时支持开始前按秒调时，计时范围最高为 59:59。离开计时页面后，顶部悬浮条显示其他模式的进度，可返回对应模式或暂停 / 继续，也可收成胶囊以减少遮挡。

### 打卡：记录每天与每周的习惯

创建习惯，设置名称、图标、每天或每周的目标，以及提醒时间。在列表中一键完成今天的打卡，通过本周标记和今日进度查看完成情况。

习惯详情提供周、月、最近一年次数与全年热力图，可以按日期查看完成状态。习惯支持编辑、归档与恢复，归档保留历史；热力图用于查看记录，不提供补卡。提醒在前台显示静默短提示，在后台通过系统本地通知送达。

### 回顾：从每日记录看到整体规律

按周或月查看专注时长、次数、专注天数和打卡情况，按番茄钟、正计时或倒计时筛选。点击图形中的日期先查看数据卡，再进入当日记录，核对每段专注和当天打卡。

独立统计页提供日均专注、最长单次、同期比较、趋势、类型占比、开始时段分布、习惯完成情况及最近一年专注热力图。回顾与统计使用同一份记录，翻期、筛选和返回时保留浏览上下文。

## 主题、反馈与应用外展示

**三套表盘主题**共享功能和操作：机械以刻度与指针表达时间，水位以水面和涟漪呈现进度，日影以阴影变化表现时间流动。每套主题均支持浅色、深色和跟随系统，并适配减少动态效果。

**声音与触感**可分别设置总开关，也可按计时模式与打卡单独配置。主题音效覆盖滴答、间隔提示和完成提醒，设置中可以试听；计时声音与触感只来自正在查看的模式，切到非计时页面保持安静。

**桌面组件**在 Android 和 iOS 展示专注状态与今日打卡进度。iOS 另提供锁屏组件、汇总实时活动与动态岛，便于在应用外查看计时，并从支持操作的入口暂停 / 继续。具体系统能力和刷新边界见 [原生组件与实时活动](docs/engineering/system-surfaces.md)。

## 本地保存与产品边界

偏好、会话、专注记录、习惯和打卡数据保存在本机，无需注册登录，不提供云同步、社交、排行榜或连续天数奖励。计时与统计围绕自己的记录展开，更换设备时数据不会自动同步。

应用异常关闭后按最后有效保存点恢复，运行中的会话恢复为暂停，不补算关闭期间的时间。完整使用规则见 [产品说明](docs/product/product.md) 与 [逻辑与交互](docs/product/logic-and-interactions.md)。

## 快速开始

建议使用与 CI 一致的 Flutter 3.44.0（Dart 3.12.0）及 Node.js 22。Android 需要 JDK 和 Android SDK；iOS 需要 macOS、Xcode、CocoaPods 与 CMake。安装、换设备和版本升级见 [开发环境](docs/engineering/development-environment.md)。

```bash
flutter pub get
flutter devices
flutter run -d <device-id>

# 完整客户端检查
node tool/verify.mjs
```

## Android 打包与发布

进入 [Android build · 打包与蒲公英发布](https://github.com/xinqingaa/yike/actions/workflows/android-build.yml)，点击 **Run workflow**，选择 `main` 和所需操作：

| 操作 | 结果 |
| --- | --- |
| 发布到蒲公英（默认） | 完整检查、正式签名构建、上传并确认发布，Summary 提供下载链接与二维码 |
| 只构建正式 APK | 完整检查、正式签名构建，在运行页面下载产物 |
| 只构建内测 APK | 完整检查、临时 debug 签名构建，仅用于构建核验 |

main 推送和 PR 更新只运行检查，不打包；纯 Markdown 变更只检查文档。APK 构建与发布均按需手动触发，产物保留 30 天。Secrets、长期签名备份、包体优化及故障处理见 [Android 构建与发布](docs/engineering/android-build.md)。

本地可运行 `node tool/build-android.mjs --preview` 构建内测 APK；正式包使用长期签名。云端内测包使用临时签名，日常手机安装和后续覆盖更新应使用同一长期正式签名。

CI 在 GitHub runner 上独立准备 Flutter 3.44.0、Node.js 22、Java 17、Android SDK 36、NDK 28.2.13676358、CMake 3.22.1；本地换设备不会改变云端环境。升级入口和兼容性说明见 [环境版本与配置位置](docs/engineering/development-environment.md#环境版本与配置位置)。
