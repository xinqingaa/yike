# 协作与工作流

一刻采用 Flutter 开发，产品、交互与工程规则由本仓库维护。日常工作依据文档与代码，不阅读 PBWork 原型 / Vue 源码或调用 ProtoBridge MCP。

## 开始工作

先读根 [README](../README.md)、[文档索引](README.md) 与 [已知缺口](known-gaps.md)，检查工作区已有改动。按任务阅读所属规范和真实调用点，不要求每次阅读全部文档。

本仓库只维护一刻应用。保留无关未提交内容，不修改 Producer、不复制 Evidence Store，不为普通 Flutter 任务重新采集原型或同步 DS。

| 任务 | 阅读入口 |
| --- | --- |
| 功能与业务修复 | [产品](product/product.md)、[交互](product/logic-and-interactions.md)、所属 feature 与行为测试 |
| UI 与动效 | [UI](product/ui-design.md)、[动效](product/motion.md)、组件与主题规范 |
| 架构、状态与存储 | [架构](engineering/architecture.md)、[状态](engineering/state-management.md)、[运行时](engineering/runtime.md)、[存储](engineering/storage.md) |
| 环境与构建发布 | [开发环境](engineering/development-environment.md)、[Android 发布](engineering/android-build.md) |
| 原生组件 | [系统展示](engineering/system-surfaces.md)、路由与运行时规范 |
| 测试与性能 | [测试](engineering/testing.md)，按变更选择行为、原生或 profile 验证 |
| 明确要求的原型迁移、固定证据或 DS 同步 | [ProtoBridge 专项](integrations/proto-bridge.md) 与对应仓库 Skill |

产品文档说明能力、操作和结果，工程文档说明职责、接口和限制；代码及测试用于核对文档。未明确的业务、导航或产品风格取舍先说明影响并交用户决定；普通工程细节按架构自主处理，不回读旧原型寻找答案。

## 实施与 Git 授权

用户要求先评估或制定计划时，只读核对并提供范围、文件和验证方式，获得同意后再实施。普通实施请求按任务直接完成；批准范围内不逐批重复申请确认。遇到新产品选择或超出范围的操作，只暂停依赖该决定的工作。

未经用户明确允许，不执行 commit、push、远程合并或发布。批准计划、要求开始实施或完成修复不代表授权提交、推送；默认将改动留在工作区。触发蒲公英发布也须在用户明确授权范围内。

小改动可在 main 工作，较大功能使用临时功能分支和 PR；不维护长期 dev 或专门打包分支。采用这些分支方式不改变 Git 授权要求。清理分支前核对远程状态、合并结果、独有工作与 worktree；只删除获准对象，分支清理授权不包含代码提交推送。不自动重置用户改动或强制推送。

## 验证与交付

普通代码任务运行 `node tool/verify.mjs`；纯文档任务运行 `node tool/check-docs.mjs` 并核对内容。校验工具变化补充允许 / 拒绝场景，按需运行完整入口。客户端检查不依赖外部 Producer，DS 检查只在显式专项执行。

按改动补充必要原生或性能验证；已经通过的检查不无故反复运行。分别报告代码检查、行为测试、原生目视和性能测量。截图不证明动画过程，模拟器不证明真机性能；性能结论须有实际测量数据。

交付说明最终行为、主要文件、验证及实际限制；未经授权时明确保持未提交状态。验证按改动范围安排，不生成冗长验收流水。

## 文档维护与引用

README 是项目、运行和打包入口；AGENTS 是协作入口；主文档统一放在 `docs/`。产品或工程变化直接更新所属文档，必要的选择理由与约束写在对应规则旁。文档以完整能力和机制组织，不使用阶段编号、完成状态、用户批准记录或变更流水串联正文。具体问题和测量边界归入已知缺口。

规则由一处主文档拥有，其它位置用链接导航。仓库内用相对链接，移动或删除文件时同步索引、锚点、Skill 和机器索引；生成目录不承载规范。不通过本机绝对路径或相邻仓库链接维护当前规则。

外部参考通常应使用固定提交的 GitHub 文件。项目操作入口允许精确列入 `tool/check-docs.mjs` 的白名单，例如本仓库 Android Actions 页面；这不放宽任意外链或跨仓库文件限制。文档校验检查目标、锚点与边界，内容仍须人工核对配置与实现。

原型迁移、固定 Evidence、还原验收和 DS 同步仅在用户明确要求时启用对应专项；提供旧 Handoff ID 或修改公共组件本身不触发。专项固定引用、风险与报告约束见 [专项文档](integrations/proto-bridge.md#专项流程与交付)。
