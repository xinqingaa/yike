## 已看见的边界：启动时核对，不能擅自作答

这些是交接时识别的待核对事项，不是用户已批准的产品方案，也不是要求新对话一次性抛出所有问题。先核对真实代码与规范，能从已有明确规则解决的直接解决；确实仍有取舍再集中提出具体问题。

1. **59:59 自动完成与记圈 UI**：旧阶段 3 写“会话结束后挂件 / 列表移除、面板关闭”，而已接受规则要求自动完成保留完成态与计圈。须区分“计时自动完成”与“结束 / 清除会话”，确定完成时面板、挂件和控制按钮行为，不能把计圈直接丢掉。
2. **记圈统计样本与并列**：最快 / 最慢 / 平均是否只取已完成圈；不足 2 圈的计数口径、并列标签与完成态最后一段如何处理，需确认未明确之处。
3. **统计比较与分母**：当前未结束周期与上一期比较是否按相同进度；每周习惯在月视图中的跨周、部分周应完成次数如何计算。草案只给了方向，不代表这些组合已决定。
4. **统计筛选组合**：类型环与全页类型筛选如何共同呈现；趋势柱点击后当前周期超出“最近 N 期”时窗口如何移动；不能自行设计一套联动逻辑。
5. **单次、时段与跨日记录**：最长单次应核对原会话与日期分片的关系；时段分布按原始开始小时统计时，期间只取部分跨日记录的具体归属必须一致，不能重复统计会话或误用分片开始点。
6. **新数据卡的触感来源**：当前服务按 pomodoro / stopwatch / countdown / habits scope 门控，没有独立 review 配置；回顾图形“选择震动”究竟归哪个来源或只受总开关，若规范未明确须问用户，不直接绕过服务调用系统触感，也不擅自新增一组设置。
7. **数据卡与无效日期**：回顾未来日期不响应、习惯卡草案又列有“创建前 / 范围外”状态，需分别核对有效命中区域与可查看状态；不默认两类图形有完全相同的可点击规则。
