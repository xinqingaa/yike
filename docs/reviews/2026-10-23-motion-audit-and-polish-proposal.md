# 动效复审与页面精修提案

> 本文为前轮复审背景。用户接管后的最终范围见 [最终指令](../decisions/2026-10-23-page-refinement.md#用户接管后的最终指令)，以下提案不再作为当前实施规格。


日期：2026-10-23。审查基线：`8480b88`，开始时工作区干净。本文完成源码复审、工程检查、验收探针和 iOS 原生过程复跑；页面精修为待确认提案，尚未修改应用实现及已批准的产品规则。前轮目标与结果分别见 [动效计划](2026-10-23-motion-implementation-plan.md)、[实施记录](2026-10-23-motion-implementation.md)。

## 结论

现有分层方向合理，可以继续精修，无需重写业务或引入新状态框架。本轮未在所查路径发现动画结束后才提交业务、逐帧写盘或保存重试重复结算的问题；这不等于全仓库无缺陷。工程检查与现有过程测试通过，但存在可量出的布局不一致、文字适配和读屏缺陷，不能据此宣布产品体验全量验收通过。

用户指出的专注三模式差异、打卡整页滚动、设置步骤过多、回顾缺少周期检索和类型交互、热力图边框过重均有源码依据。两处需要澄清：计圈没有三条数据上限，只是可视区域固定为两或三行；周/月本身已有范围汇总，缺的是快速定位、筛选和层次清晰的浏览路径。

## 源码发现与优先级

### P2：同主题的三模式没有共用布局锚点

[FocusPage](../../lib/features/focus/pages/focus_page.dart) 的 `_panel` 仅为倒计时重新计算表盘宽度；顶部间距又分别根据模式和 `compactLaps` 决定。动画只让这些变化过渡，不能消除布局规则的差异。

390×844、默认字体、浅色、待开始状态的 Widget 测量如下，单位为逻辑像素；数值是布局结果，不是原生字体视觉评价。

| 主题 | 番茄钟：顶部 / 宽度 | 正计时：顶部 / 宽度 | 倒计时：顶部 / 宽度 |
| --- | --- | --- | --- |
| 机械 | 144 / 312 | 144 / 312 | 120 / 296 |
| 水位 | 128 / 228 | 114 / 228 | 120 / 212 |
| 日影 | 128 / 278 | 114 / 278 | 120 / 262 |

相关源码：`focus_page.dart:425` 的尺寸分支、`:477` 的间距分支；[LapList](../../lib/features/focus/widgets/lap_panel.dart) 第 81 行固定两/三行高度。[CountdownChoices](../../lib/features/focus/widgets/countdown_choices.dart) 明确使用两列快捷项和独立的自定义行，增加了预留高度。

建议先建立公共专注布局壳，再调整动效。不能继续为某一个模式单独减小表盘来解决辅助区拥挤。

### P2：月历打卡次数容器忽略系统文字缩放

[ReviewPage](../../lib/features/review/pages/review_page.dart) 第 635 行用未经过 TextScaler 的字号乘行高固定次数区域。320×640、文字缩放 1.6、有当日打卡时，三主题的“1次”都只有约 11.22px 布局高度，而自然文字高度为 18px。当前测试没有抛出布局异常，文字仍受到高度约束；“没有 overflow 异常”不足以验收文字完整性。

修复应按缩放后的文字度量保留一行高度，并检查完整字形和相邻行间距。不能通过固定更小字体或忽略系统字号解决。

### P2：月历隐藏了统计的读屏信息

[CommonMonthCalendar](../../lib/common/widgets/charts/month_calendar.dart) 第 230 行使用 `dayLabels[date] ?? date`，随后排除子树语义；回顾调用没有提供 `dayLabels`。结果是日期按钮能被找到和点击，但专注时长、打卡次数和今天状态不能通过该日期节点读出。补充每日期的完整说明，保持未来日期禁用，不给退出中的旧日期重复语义。

### P2：习惯一周记录没有可访问的替代描述

[CheckinPage](../../lib/features/habits/pages/checkin_page.dart) 第 314 行把全部 `_WeekDot` 排除在语义树外，卡片只有本周次数，没有逐日状态的替代说明。改成星期字母/汉字与色块后，也应增加一份卡片级的周记录摘要或可导航的日期说明，避免仍只靠颜色表达信息。

### 体验问题：打卡页滚动职责和装饰层级

标题、进度、星期表头、习惯与归档入口都是同一个 [MotionList](../../lib/features/habits/pages/checkin_page.dart) 的条目，因此整页会滚动。顶部“一—日、今天”是列说明，不是日期筛选器；它在视觉上与卡片内记录的对应关系不够直接。

卡片使用 [CommonGlassSurface](../../lib/common/widgets/display/glass_surface.dart)，有边缘与阴影绘制。卡片左右下角色块的确切来源尚未通过单独隔离图层确认，不应直接定性为绘制缺陷；精修时先将内容卡片替换为安静的实体材质，再对三主题浅深模式做目视核对。全局玻璃组件不需要为了内容卡片而重写。

### 体验问题：设置与回顾的结构

[设置](../../lib/features/settings/pages/settings_page.dart) 将常用倒计时组织成 FlowSheet 列表 → 编辑 → 保存 → 返回列表 → 完成。确认、保存和关闭职责混合，简单偏好调整显得繁琐。当前这是已实现的旧交互规则，不是落盘错误。

[回顾](../../lib/features/review/pages/review_page.dart) 已计算周/月汇总，但标题是普通文本，类型区也是静态文本与进度条；没有周期选择器或类型筛选状态。每日记录正文还被额外限制为屏幕高度的 `panelMedium`，本地值为 0.5，且未在调用处配置可扩到全高的停靠点。

## 动效验收

### 回顾日期与正文

当前源码的范围标题和统计正文都使用 [MotionPage](../../lib/common/motion/page_transition.dart)，该组件没有 FadeTransition。追加的页面级探针分别检查翻周、翻月：70ms 中间帧两个区域的水平位移比例均为 `-0.3581984192`，没有淡入淡出子树。本轮不能复现“标题翻页、日期淡入淡出”的源码现象。

这不否定设备上观察到的现象，也不据此猜测原因。后续精修验收应记录实际运行的构建版本，并同时观察标题、日期、图形；不要只测公共 MotionPage。当前两个区域由各自控制器驱动，下一轮可由回顾过渡壳统一翻期输入，避免将来只修改其中一处。

### 已通过的边界

- 业务状态、动画投影与写盘分离；表盘帧只更新局部 DialFrame。
- 完成事件按会话/阶段产生，实时可见性门控不依赖下一次 build；保存重试和返回不补播。
- 退场内容排除点击、焦点和语义；减少动态效果保留最终状态。
- 未保存浮层由应用层持有唯一句柄，模态结束依据实际 dismissed 生命周期恢复。
- 现有测试覆盖中断、返回、快速打卡撤销重做、整小时、暂停、保存失败和嵌套模态。

以上是所读源码与本轮测试覆盖的结论，不代表真机帧耗时或全部原生辅助功能通过。

## Apple 设计研究与产品取舍

本轮直接查阅 Apple Human Interface Guidelines 的 Motion、Layout、Typography、Sheets、Charts 页面，查阅日期为 2026-10-23。下面归纳为本地设计依据，实施无需依赖外部网页：

| 官方原则 | 对一刻的具体含义 |
| --- | --- |
| 布局按重要性排序、统一对齐，渐进展示辅助内容 | 表盘和主操作稳定；计圈详情、滚轮与周期选择按需展开 |
| 动效有目的、简短、可中断、可减少 | 翻期表达时间方向；相邻信息共用方向和节奏，不增加持续装饰 |
| 用字重、字号和颜色表达层级，避免过细字体，支持 Dynamic Type | 机械主题降到 Regular/Medium；不能直接照搬水位的 Thin，也不能削弱系统粗体设置 |
| Sheet 服务一个范围明确的任务，高度服从内容，可提供多个停靠点 | 常用项一个面板内编辑；每日长记录可扩到全高；简单设置不必全屏 |
| 图表先表达信息，再提供有价值的交互；不能只靠颜色 | 默认就能看懂周期总量；类型支持筛选；热力图状态同时有文字和语义 |

官方并未要求每段标题都可点击，也未要求所有 sheet 都删除确认。本文建议为需要浏览的周期标题增加入口，普通分组标题保持静态；普通偏好自动保存，删除/重置继续保留明确确认。这些是针对一刻的产品判断。

## 精修方案

### 专注：共同骨架和可伸展的辅助区

顺序为：日期与今日汇总 → 三模式 Tab → 固定呼吸间距 → 主题表盘 → 辅助区 → 固定主操作。相同主题、相同视口和文字设置，三模式使用同一表盘尺寸与中心；保留各主题自身比例，不强求三种表盘外形相同。

尺寸由同一布局计算结合可用空间和三模式共同需求决定，不再依赖当前模式分别计算。正常手机尺寸优先保留表盘和主操作；极窄屏或大字采用共同紧凑布局，并允许必要的内容滚动，不能硬裁切或把表盘无限缩小。

- 番茄钟：辅助区只放轮次与下一阶段说明。
- 正计时：保持 Tab 到表盘的统一间距；计圈区占剩余空间，按可用高度展示更多行，独立滚动。提供“全部 X 圈”进入可扩到全高的列表，保留当前圈、单圈、累计三列和新圈局部插入。不限制数据数量，也不为显示更多行挤动表盘。
- 倒计时：四个有效常用项改为一行，采用紧凑时间标签；下方只保留“自定义”文字入口，已选自定义时长由表盘读数表达。空槽不占可点击位置。超长值和大字时允许这一行横向滚动，保持有效触控目标，不强行压成四个窄按钮。
- 三模式的主操作保持共同位置；运行、暂停、休息、完成时只变化所需标签与次操作。

### 机械主题：从全局文字角色降低重量

在 TS 的 Flutter 自有类型化扩展点统一覆盖机械文字角色，先应用再插值和度量；不手改生成主题，也不启动外部 DS 同步。

建议表盘数字与数值标题使用 400，主标题 500，内容及快捷时长 400，必要的强调用 500；选中态优先通过底色/文字色表达。移除快捷项自行加到 600 的局部覆盖，保持数字等宽与稳定字槽。机械感由刻度、指针和比例承担。系统粗体、浅深色和字体缩放仍生效；最终字重须以原生字形目视确定。

### 打卡：固定标题、移除全局星期表头

顶部只保留“打卡”、今日完成进度、新建入口；中间习惯列表是唯一主要滚动区，归档入口置于列表末尾。空态也在同一内容区，不出现双重新建入口。

每张卡片第一行是图标、名称、目标/次数和详情入口；第二行是“一 二 三 四 五 六 日”与独立的今日打卡按钮。完成日使用小型实心色块并附完成语义，今天使用轻标记，未来与创建前分别弱化。星期只是记录，不伪装成筛选器，也不开放补卡。

“一个选中代表一周”容易混淆，应明确为“一格代表一天，七格合起来是一周”；每周目标继续以“本周 3/4 次”等摘要表达，不能把周目标次数与日期格混为一种刻度。

内容卡片使用实体浅底与留白，去掉玻璃边缘和装饰阴影；操作层仍可保留现有玻璃语言。触控按钮保持足够尺寸，视觉上的小色块不成为小点击目标。

### 设置：有效选值落定即保存

普通设置不再有底部“确认/保存/完成”。单个时长或长休间隔是紧凑单页 sheet，保留顶部关闭入口；四个常用倒计时使用约 75% 高度的单页 sheet，允许扩到安全区内全高。点击任一行在该行下展开滚轮，同一时间只展开一项，不再进入 FlowSheet。

滚轮的滚动过程中只更新草稿，停止并吸附到合法组合后自动提交；关闭前若已有合法落定值则保留。默认值、空槽初始占位或打开面板本身不能触发保存。时分秒多列切换需要合并落定，避免逐帧写盘。

- 零时长、超范围、重复槽位：就近显示错误，保留草稿，之前的有效值继续生效；关闭丢弃尚未合法接受的组合。
- 清空、恢复默认：作为靠近对应内容的明确动作，立即生效，不再追加一轮“完成”。
- 写入失败：区分已接受但未落盘与校验拒绝，保留“尚未保存”及重试；没有完成按钮不等于删除错误恢复路径。不要借故重试再执行一次业务。
- 短时阈值：同一页放预设选择与内联自定义滚轮；有效选值落定后自动保存。
- 重置：保留后果说明与明确二次确认，不纳入普通偏好的自动保存逻辑。

自动保存仅用于设置偏好；不把其它业务表单、习惯编辑或专注中的临时选择全部改成自动提交。

### 回顾：从静态陈列改为周期浏览

顶部第一行“回顾”与返回当前周期入口；第二行左侧为周/月分段选择，右侧为上一期、下一期操作，中间/下方的日期标题成为可点击的周期入口。窄屏按两行排，不把长日期挤进剩余空隙。去掉当前两条整宽分割线，以间距分组。

点击日期标题打开周期浏览面板：按年切换，月维度列出月份及月汇总，周维度列出日期范围及周汇总；选择后回到对应图表，不增加另一个根页面。保留当前周期定位、历史空期可浏览、未来不可进入和上次浏览日期的跨维度定位规则。

正文先展示当前范围的专注时长、次数/天数、打卡数，再展示周柱形或月历。类型区改为“全部 / 番茄 / 正计时 / 倒计时”的轻量筛选；图形、类型相关汇总和每日专注记录使用同一筛选。打卡继续独立计数，明确显示，不能因为选择计时类型就消失。周/月与前后翻期保留当前筛选；退出页面返回仍保留本次浏览上下文。周期浏览面板的数字应与当前筛选保持同一口径。

主图默认传达总量，无需点击才能看见关键信息。日期点按进入每日记录，面板可在约 75% 与安全区内全高之间切换；标题/关闭/翻日区固定，正文独立滚动。日明细仍逐日移动、不跳空日、不进入未来，也不跨打开时的周期边界。

这不是给所有标签添加跳转；“按类型”等分组标题仍是说明，只有可执行动作才获得按钮语义和按压反馈。

### 习惯详情：柔和的二值完成热力图

当前已经是最近 365 天、按周排列的热力图；本轮改变视觉和阅读层次，不新建另一套记录统计。先显示名称/频率、周目标及周月年摘要，再显示最近一年完成记录。

去掉每格边框：完成用主题实色，正常未打卡用轻中性填充，创建前/范围外留白，归档未完成用单独弱化状态。完成事实始终优先。一天最多一次打卡，因此不用“少—多”多级强度制造数量含义。

保留月份定位、最近日期默认可见和水平浏览；星期轴减少重复文字但不丢语义。大字时格距和标签高度共同适配，不能继续用固定小格高度约束放大的星期文字。图例有明确文字，增加对比度时恢复必要的形状差异或标记，不要求永远只靠纯色区分。

## 实施落点与架构约束

| 批次 | 主要落点 | 边界 |
| --- | --- | --- |
| A：回归缺陷 | review 日期说明与次数高度、habits 周记录语义、相关测试 | 优先修复可量出的缺陷；将探针转为行为回归 |
| B：专注与字重 | focus 页面布局壳、CountdownChoices/Utility、LapList、theme 本地排版扩展 | 复用 FocusDial，不改 FocusEngine、会话身份及计圈事实 |
| C：打卡与详情 | CheckinPage、私有习惯卡片、HabitHeatmapPlot | 保留打卡/撤销规则和 365 天查询，不开放补卡 |
| D：偏好面板 | settings 私有面板与草稿 Provider、公共滚轮落定回调、AppPop 尺寸配置 | 自动保存与瞬时草稿分开；不改统一弹层库源码 |
| E：回顾 | ReviewSelection/展示 Provider、周期浏览、类型筛选、DayDetailSheet | 统一派生查询，保持 session 去重、跨日分摊和统计秒数精度 |

现有 `common/motion` 不导入 feature、控制器随 Widget 释放、事实来自 local_data 的方向应保留。需要改善的是页面组合过重：[FocusPage](../../lib/features/focus/pages/focus_page.dart) 混合模式决策、布局和控制，[settings](../../lib/features/settings/pages/settings_page.dart) 同文件拥有所有草稿与流程，[ReviewPage](../../lib/features/review/pages/review_page.dart) 反复做日期与类型过滤。按上述实际职责拆分私有 Widget/展示查询即可，不建立万能页面基类或新的 Repository 层。

统计应从同一份记录生成按日、按类型、按周期索引再供页面使用，避免为周期浏览再复制一套口径。大历史查询、机械周图分隔线数量随量程增长及单快照写入仍需规模测量；本轮没有测出性能退化，不能把源码复杂度当成卡顿结论。
