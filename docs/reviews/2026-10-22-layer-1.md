# 第一层 UI 交付记录

本轮完成机械、水位、日影三主题的 UI 骨架，包含浅色、深色和跟随系统。七个 Screen 已落地，页面导航、表单与展示状态由 Riverpod 驱动。第一层不推进真实计时，不结算历史，不持久化业务数据；这些属于第二层，业务动画属于第三层。

固定来源：Workspace `pbwork-local`；Handoff `handoff-2026-10-22t083440493-0b17323b`；Bundle `bundle-2026-10-22t082823167-26f4539d`；Snapshot `snapshot-2026-10-22t083354783-d240a8ad`。原始 `mandatoryRisks` 为 `[]`。固定 199 revisions/Cases、187 份不同截图已通过 MCP 读取并目视；215 个规则派生外观不计为实际截图。

## 实现范围

专注页包含三种计时模式及准备、运行、暂停、完成、休息、恢复等展示模型；表盘采用 DS 资源与静态图层裁切。打卡包含四个固定初始习惯、七天标记、独立详情入口、打卡入口、新建和归档入口。习惯详情包含统计、365 日只读热图和管理动作；编辑面板包含名称、图标、频率、周目标、提醒以及固定底部保存操作。回顾包含周／月导航、汇总、三主题图形、类型分布和可独立滚动的日期明细。设置包含三个真实表盘预览、外观、时长、常用项和阈值 FlowSheet，以及重置确认。启动页展示品牌表盘，准备完成后直接进入根页面。

页面与展示模型在 `lib/features/yike/`；表盘与布局组合在 `lib/common/widgets/yike/`；资源登记和比例在 `lib/theme/yike_artwork.dart`、`lib/theme/yike_geometry.dart`；路由在 `lib/router/`。共享 AppBar 增加文本动作，LaunchScreen 增加内容和页脚，AppPop 修正弹层 Material 上下文并支持 Toast 避让底部导航。主题偏好加入 `system` 并以机械为默认。生成的主题文件没有手工修改。

## 已知偏差和剩余风险

- 第一层的计时按钮和表单只改变内存展示状态。实际 tick、跨日归属、结算、恢复、保存失败和重开验证待第二层；撤销仅最近一次的完整业务语义也待第二层收口。
- 水位读数尚未实现水下同步反色副本；轮次水滴、部分打卡形状与日影阴影裁切仍为首版近似。字体、阴影、表盘位置与页面间距没有完成全部固定 Case 的逐项视觉比对。
- 基线 `AppMetrics` 会限制部分文字尺寸；这影响源截图与 Target 的字号一致性。映射和门禁通过不能代替视觉接受。
- 公共 AppBar 的底边线与弹层默认关闭图标可能与源图不同；编辑、新建和管理反馈也尚未逐个截图验收。
- 回顾空态保留固定 Screenshot 的“去专注”按钮；它与 `docs/product.md` 中根页面正文不另设跨根主动作的要求冲突，待用户决定最终行为。
- 启动页只在启动准备时出现；未人为增加停留时间，尚未逐主题捕获 Target 启动首帧。
- 提醒和提示音仅提供配置 UI，不调度通知或播放声音；动效尚未实施，固定 Evidence 也不提供正常时间轴 authority。

本轮为阶段性 consumer review，尚未达到完整还原验收。五维观察与目标校验结果另存于同目录 receipt；缺失观察保留为 partial，不补写无依据的 matched。

本阶段提交 16 条人工观察：7 matched、4 deviation、5 unverified；判据仅限各条 detail，不代表整页或全部 Case 已匹配。仅标记 7 个默认 UI Case 已处理，0 个固定数据完整 Scenario 已重放。各 Screen 的 components、states、interactions 义务已读取；structure 与 tokens 的实施后义务只读取首个分页，因此五维复核仍为 partial。前期全部 Screen packet、Case delta 和不同截图的读取不受此影响。

`summarize_reconstruction_review` 调用失败，返回：
`Unknown review requirement obligation-sha1:68fcd4a2371a6ce8648997a1e8f72e23d9aa854a.`
只读检查发现服务端 `read_reconstruction_obligations` 使用去重 `obligationId`，汇总方法则直接读取旧 acceptance contract 并校验逐 Case 的 `requirementId`。两条路径没有兼容转换。这是 Review 接口的服务端协议缺口；本轮没有修改 producer，也没有用空 observations 假装汇总成功。16 条观察和失败原因已保留在 receipt。

证据经项目配置的同一入口 `node tool/mcp.mjs` 使用独立 stdio 会话读取。Codex 注册连接曾出现 `Transport closed`；该断连根因尚未定位，不能据此归因于配置。Review ID 缺口与证据可读取是两个不同结果。
