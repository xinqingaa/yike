# 原生组件与实时活动

本页维护 WidgetKit / ActivityKit 与 Android RemoteViews 的实际能力、展示协议和外部命令边界。产品动作见 [交互规则](../product/logic-and-interactions.md#桌面组件与实时活动)，Android 卡片布局见 [UI 规范](../product/ui-design.md#android-桌面组件)，生命周期见 [运行时](runtime.md#桌面组件与实时活动运行边界)。

## 展示矩阵

所有三模式列表按番茄 → 正计时 → 倒计时固定顺序。仅能显示单模式的尺寸优先运行中距到点最近者，正计时按距 59:59 上限比较，同时间用固定顺序；无运行态再选暂停态。习惯按打卡页进行中顺序，前三项或首项仅限制展示，今日 N/M 始终统计全部进行中习惯。

| 平台 / 类型 | 内容 | 导航与动作 |
| --- | --- | --- |
| iOS 专注 Small | 优先模式、时间及状态 | 打开该模式，只读 |
| iOS 专注 Medium / Large | 最多三模式、时间 / 状态 / 进度，空间允许时提供轮次 / 圈数及今日时长 | 按展示身份定位，可用操作最多暂停 / 继续 |
| iOS 打卡 Small / Medium | 今日 N/M；小尺寸首项，中尺寸最多前三项及完成状态 | 打开打卡，支持时定位习惯，不打卡 |
| iOS 锁屏 Circular | 今日打卡进度；无习惯时不伪造完成环 | 打开打卡 |
| iOS 锁屏 Rectangular / Inline | 优先专注及时间 / 暂停状态 | 打开对应模式 |
| 汇总实时活动 / Expanded 动态岛 | 同一活动内最多三模式，包含休息，暂停保留 | 按行定位，操作最多暂停 / 继续 |
| Compact / Minimal 动态岛 | 优先模式图标、时间及必要状态 | 打开实际展示模式 |
| Android 专注 4×2 / 4×4 | 按实际一至三会话组织紧凑 / 分组布局；大尺寸增加进度及今日已记录时长 | 按行定位，空间允许时提供暂停 / 继续 |
| Android 打卡 2×2 / 4×2 | 今日 N/M，首项 / 前三项及完成状态 | 打开打卡，按能力定位，不打卡 |

没有运行 / 暂停会话显示专注空态，不提供外部开始按钮；读取失败与真实空数据分开呈现。长习惯名可截断但读屏保留全名，时间等宽且布局宽度有界。三主题共享信息结构和必要颜色，不复制 Flutter 表盘动画。

## 平台能力与降级

| 能力 | 当前处理 |
| --- | --- |
| iOS 15 | 主屏 Widget；读数使用带更新时间的安全静态值，无锁屏 Widget 或实时活动 |
| iOS 16 | 锁屏 Widget 与有界系统时间文本，读数可按锚点推进并封顶 |
| iOS 16.1 起 | 按系统能力提供实时活动及支持设备上的动态岛；非动态岛机型仍可显示锁屏活动 |
| 外部暂停 / 继续 | 当前通过打开应用进入唯一 Flutter 业务写入者；不因系统支持 App Intent 就另建后台业务进程 |
| Widget 时间线 | 提交已知到点及日期边界，事实变化请求 reload；系统预算决定实际刷新，不能保证到点即时换行 |
| Live Activity | 无 Widget 时间线；系统时间文本可推进，优先模式、文案和结束仍需应用执行机会，`staleDate` 不执行任务 |
| 活动寿命 | 自然完成后从实际结束提交起请求锁屏保留约 5 分钟，系统 / 用户可提前移除；长暂停受平台回收限制 |
| Android | 事件刷新及系统受限的 30 分钟更新，安全静态封顶读数带更新时间；不使用常驻服务或 Chronometer 代替业务状态机 |

任一会话开始后创建 / 更新同一汇总活动；某模式完成不影响其它运行 / 暂停模式。全部自然完成时提交静态结果并结束，动态岛随结束移除；清空所有会话、关闭活动开关或重置时请求立即移除。实时活动开关默认开启，与通知总开关及系统权限分开。

应用没有后台执行机会时，结构切换、完成文案及结束可以延迟；下次运行校准。异常终止后旧锚点可能暂时仍显示，冷重开按最后保存点恢复暂停并覆盖旧投影，不补算关闭时间。Android 锁屏只保留到点提醒，不新增持续计时通知或小米超级岛。范围不含服务端推送、后台常驻、外部开始 / 结束 / 放弃 / 打卡、macOS Widget 或 iPadOS 专项交互。

## 共享展示协议

唯一业务事实仍在 AppPrefs / MMKV，平台只能读取可重建展示缓存。`common/system_surfaces` 定义版本化 DTO、意图与平台适配；`app/system_surfaces` 消费公开业务投影，组合主题并协调串行发布。iOS 经 App Group 容器共享，Android 使用应用私有缓存；原生原子替换，不直接读写 MMKV。

| 数据组 | 约束 |
| --- | --- |
| 外壳 | 格式版本、重置代次、revision、生成时间、本地日期 / 时区、可读与保存状态 |
| 专注 | 模式、会话 / 阶段身份、状态、固定目标 / 量程 / 上限、有效用时、锚点、轮次 / 圈数、允许动作 |
| 汇总 | 今日已记录时长沿用同一统计口径，三模式分别累加，不重复累计完成会话与已入账记录 |
| 习惯 | 全部进行中习惯的今日 N/M，以及前三项所需身份、名称、图标、顺序与今日状态 |
| 外观 / 能力 | 主题及必要颜色、资源、实时活动开关与系统能力，不等同于通知权限 |

按语义变化去重，250ms pulse 不触发全量序列化或原生调用。日期过期、未知格式或读取失败不能呈现初始化假习惯；保存失败可展示已经接受的内存结果并标注未保存。清理与发布串行，重置先撤销代次，再等待在途发布并清理，旧写入不能恢复旧展示。

## 外部目标与命令流

1. Swift / Kotlin 接收 URL 或 PendingIntent，严格区分查看与 pause / resume，校验版本、动作白名单、模式、会话、阶段、重置代次、预期状态及 token。
2. 打开应用并等待存储及唯一业务作用域就绪。读取受阻不能以初始数据执行；内容点击不隐式变成命令。
3. 串行入口先校准最新事实，再校验身份。暂停 / 继续为明确动作，不能用 toggle；重复投递不能反向操作或命中新会话。
4. 保存消费回执后调用 `FocusActions.commandResult`。状态转换 token 仅在本进程有效，冷进程旧动作只定位并提示更新；不另建原生计时器、isolate 或写入者。
5. 查看目标经 `app/external_targets.dart` 等待启动就绪和模态安全退场，不丢草稿、不重复压根页；命令消费与导航等待分开，不能反复执行。
6. 接受命令后发布最新展示。命令拒绝、内存接受、业务保存和原生展示更新分别表达，重试不重放业务反馈。

`system_surfaces` 元数据保存版本、代次、开关与有界消费回执，具体存储规则见 [存储](storage.md#原生展示缓存)。组件删除、活动被拒绝或回收不改变业务会话和统计。

## 原生维护与验证

Android API 31 起使用宿主尺寸集合，缺失时组合横竖屏宽高；旧系统使用横竖屏 RemoteViews。占格、可用区域、可见卡片和内边距分开，按实际会话数量排版，不硬编码厂商像素差。复用 RemoteViews 时显式恢复各状态可见性，原实例优先通过更新生效；启动器要求重新添加时说明具体限制，不自动删除用户组件。

系统 `Text(timerInterval:)` 必须有有限宽度，避免 `fixedSize()` 请求无限理想宽度并在归档渲染中造成 NaN。修改后实际检查锁屏 / 动态岛运行读数，构建成功或普通应用内 SwiftUI 渲染不能替代系统展示。

变更时按受影响平台检查尺寸、三主题浅深、缩放、单 / 多会话、暂停 / 完成 / 空态 / 错误、行与按钮身份、冷启动和重置。更改后台能力须核对实际系统限制；验收完成不代表所有厂商、辅助功能和耗电组合均已有测量数据。
