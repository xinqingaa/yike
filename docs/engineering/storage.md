# 本地存储

本文拥有存储接口、键白名单、快照与失败处理规范；产品恢复语义见 [逻辑与交互](../product/logic-and-interactions.md)。

只通过 `AppPrefs` 访问 MMKV。生产实现为 `MmkvAppPrefs`，由 `AppStartup` 等待初始化成功后 override `appPrefsProvider`。单元与 Widget 测试使用 `test/support/fake_app_prefs.dart`，原生集成测试单独验证真实 MMKV。生产实例为 `yike`，当前偏好 key：

- `theme_mode`：`light` | `dark` | `system`（一刻默认跟随系统）
- `theme_pack`：已注册的类型化主题包 ID
- `notification_metadata`：版本 1 调度元数据：稳定预约 ID、成功预约截止时刻、习惯每日机会消耗；不保存会话或打卡副本。重置一并清理。
- `system_surfaces`：版本 1 原生展示元数据，保存重置代次 `epoch`、默认开启的 `liveEnabled` 与最多 64 个已消费命令回执 `consumed`；不保存会话 / 习惯副本。首次生成与重置先保存代次，失败禁用外部动作并允许重试。共享 JSON 文件为可重建展示缓存，不是 MMKV 业务入口。
- `business_snapshot`：版本化业务快照，包含初始化日期、计时偏好、会话、周期、专注记录、习惯与打卡身份。由 `features/local_data` 负责组合序列化和单 key 保存；feature 只通过 AppPrefs，禁止直接 MMKV。

计时与习惯各自保留模型与规则；跨模块快照协调放在 local_data 模块。公开的 focus_models.dart / habit_models.dart 只导出模型和纯逻辑，避免反向导入页面。单一 LocalData Notifier 拥有业务事实，页面 Provider 只派生投影；tick 不写存储，阶段边界和用户操作才保存。

`app/local_data_boundary.dart` 处理读取阻断和保存失败重试；`storage/preference_writer.dart` 保留失败的外观写入。重置由 `app/reset_data.dart` 协调业务快照、外观、根导航、回顾选择和撤销提示，feature 不相互导入私有页面。业务快照为单 key 写入，外观两项独立保存；重置任一写入失败均显示未保存状态，重试当前结果。

存储接口使用 `PrefsEntry<T>` 绑定键与 Codec，键由 `PrefsKey` 枚举限定在白名单；`AppPrefs.read/write` 调用 Codec 完成类型转换。String、bool、int、double 和版本化 JSON 均经 Codec 保存为字符串。业务 Codec、模型和校验仍在所属 feature；storage 不导入 feature。

初始化错误使用 `PrefsOpenException` 区分存储不可用与文件损坏。读取不存在的键返回 null；键存在但无法解码、底层异常、保存和删除失败均抛出含键与操作的 `PrefsException`，不把错误当作首次使用。`VersionedJsonPrefsCodec` 使用 `{schemaVersion, data}` 对象封装。当前仅接受 schemaVersion 3，旧版、未知版阻断，不自动清除或覆盖原数据。用户已选择不兼容旧格式，不提供旧版迁移。打开已有 MMKV 文件前检查完整性，异常时拒绝打开，避免默认恢复策略丢弃数据。

不要为未提交表单、测试 fixture 或截图专用状态创建生产存储。需要新 key 时先改本文白名单，再改 `AppPrefs`。

## 结果、重试与一致性

命令先在内存生效，保存结果单独反馈。bool 返回值若表示保存成功，调用方不能据此推断业务从未执行；重试保存同一最终快照，不重新调用创建、打卡或结算。新增接口应让无效动作、已接受结果与保存失败的区别可判断。

读取失败是阻断状态，不是空数据；重试读取不覆盖原始文件，只有明确确认重置才重新初始化。外观与业务的独立写入可能部分成功，未保存状态持续到全部待保存内容写入成功。动画反馈不改变这些保证。

## 版本与增长

JSON 的 schemaVersion 与业务实体身份都必须验证。真正需要发布升级时先定义旧版本 fixture、逐版本迁移、未知版本保护和失败恢复，再修改接受范围；不要把未知字段或损坏数据当作默认值静默覆盖。

同步快照适合当前数据规模。以大量专注历史与多年习惯记录测量启动、编码、写入和查询耗时，再决定拆分、索引或异步化。迁移后仍需验证会话与记录幂等、跨日归属和失败可恢复性。

## 诊断与验证

日志只记录操作、键、版本与错误类别，不输出习惯名称、完整快照或用户记录。FakeAppPrefs 用于类型/故障注入；原生 MMKV 重开与进程重启使用隔离实例，禁止破坏生产 yike 数据。测试替身不能证明磁盘可靠性，验证入口见 [测试](testing.md#原生存储验证)。

## 反馈与秒级时长格式

TimingPreferences 保留 `sound` / `haptics` 总开关及完整 `feedback` 对象，包含 pomodoro / stopwatch / countdown / habits 四个来源。三个计时来源各有 sound / haptics / secondTick（bool）、beatMinutes（0 / 1 / 5 / 10 / 15）；打卡只含 sound / haptics。读取要求字段完整且类型合法，损坏不回退默认。关闭总开关不修改局部值；试听完成音不增加偏好字段或 key。

同一 `business_snapshot` 使用 schemaVersion 3。专注 / 短休 / 长休偏好为 `focusSeconds` / `shortSeconds` / `longSeconds`，默认 1500 / 30 / 900；专注与长休 1–3599、短休 1–59 秒。四个常用倒计时非空值为 1–3599 秒且不重复，首槽必填，其余可空。用户可自行卸载或明确重置旧数据，不自动重置或迁移。

新会话目标仍为毫秒，但按整秒与阶段范围校验；倒计时另存固定 `scaleSeconds`，不从最新偏好反推；正计时支持 3599 秒上限完成态与计圈。番茄本次覆盖、倒计时待开始草稿及选中身份不持久化。版本保护、记录幂等与保存失败规则保持，行为见 [表盘调时规则](../product/logic-and-interactions.md#表盘拨动与反馈)。

## 记圈与统计的存储边界

计圈与统计沿用现有业务快照。完整圈仍只属于当前会话，手动结束后不创建圈历史。回顾/统计筛选与周期、菜单、滚动、飞行和挂件弹动均不持久化。统计使用原始分片与会话身份派生，习惯历史不新增目标版本或归档流水。

## 三模式与调度格式

用户明确无需兼容旧安装数据，可自行卸载或清空缓存。当前业务快照为版本 3 三模式结构，不实现版本 2 或更早版本的读取 / 迁移 / 兼容字段，不自动清空旧数据。新格式仍严格校验身份、范围、损坏和未知版本，读取阻断 / 手动重置的保护沿用。

三个模式的会话及通知总偏好仍在同一业务快照；各模式有效记录分别累加，重叠不去重，不新增运行区间事实。系统预约的 ID / 代次 / 习惯当日提醒机会属于调度元数据，不能成为业务结算凭证。习惯采用前台站内提示与后台系统本地通知，两路共用按习惯身份及本地日期保存的机会去重信息；重开或编辑不能重新增加当天机会。系统预约状态与实际送达分开表达，不能把预约成功当成已送达。后台总偏好与习惯自身开关分开保存，关闭后台或系统拒权不改写习惯开关，前台提示仍按自身开关生效。新增元数据 key 时先登记白名单，不增加第二份习惯 / 打卡事实。站内完成条的约 1200ms 停留、退场与已消费展示事件属于临时呈现状态，不写入业务快照；冷启动不补播完成条。业务字段为 `focus.sessions` 列表（按 mode 唯一）、`backgroundReminders`（默认 false）；每个会话保存固定 `shortSeconds` / `longSeconds` / `interval`。调度元数据独立版本 1 保存 `nextId` / `ids` / `consumed` / `scheduledAt`：截止锚点在原生调用前持久化，覆盖范围另从成功调用推导，不把截止占位当成成功送达。所选模式、完成条寿命、待开始草稿不持久化。

## 原生展示缓存

原生展示不改变业务快照版本。iOS App Group `group.com.protobridge.yike` 的 `surfaces-v1.json` 与 Android 私有 `yike-surfaces-v1.json` 保存版本 1 可重建展示 DTO，包含只读会话投影、前三项习惯及总体进度、主题和来源时刻；平台原子替换，扩展不写 MMKV。格式 / 读取错误显示“打开一刻更新”，过期日期不冒充今日习惯。

`system_surfaces` 命令回执有界保留 64 项，先于业务动作保存，失败禁用动作并提供重试，重试不重放已消费命令。进程内 token 在每次会话阶段 / 状态变化时更新，冷进程旧 token 失效；重置保存新 epoch 并串行清除缓存与活动。读取受阻不能导出初始化假习惯，保存失败则允许展示已接受事实并标注“尚未保存”。原生清理失败单独报告，不改变业务重置结果。
