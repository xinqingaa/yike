# 状态管理

Riverpod 是一刻业务与页面状态的唯一管理方式。Flutter 控制器负责局部输入、滚动、焦点和绘制时间；它们不拥有另一份业务事实。

## 状态归属

| 状态 | 所有者与寿命 |
| --- | --- |
| 会话、习惯、打卡、偏好与记录 | 公开业务 Provider；按产品规则保存 |
| 汇总、日期分配与热力图 | 从事实派生的 Provider/纯查询；不重复手工累计 |
| 根 Tab、周期选择、最近浏览日期 | 对应导航或页面 Provider；本次打开期间保留 |
| 草稿、校验、提交状态 | 编辑流程 Provider；取消丢弃，失败保留，重试复用身份 |
| 按压、焦点可见、弹层请求锁 | 组件实例的 localValueProvider，随实例释放 |
| 文本、Tab、滚动、焦点控制器 | Widget 生命周期创建与释放，业务值仍受调用方控制 |
| 动画进度、Ticker、前后画面与绘制缓存 | Widget 生命周期内的 Controller 与局部字段；用 AnimatedBuilder/ListenableBuilder 驱动局部呈现 |
| 一次性完成/打卡反馈 | 从已接受的业务转换识别，以对象/操作身份去重；不随状态重建重播，不持久化动画进度 |

逐帧变化不写 Provider 或存储。AnimationController 等 Flutter 原生 Listenable 不属于平行业务状态框架。使用 State 的字段保存控制器、订阅和动画前后值，不通过这些字段复制会话、表单或统计。

## Provider 使用

Notifier/AsyncNotifier 负责可写状态和命令，Provider 负责纯派生，FutureProvider 负责异步准备。使用不可变快照，不原地修改集合后期望消费者自动更新。

`ref.watch` 读取渲染所需数据；`select` 限制到实际依赖的字段；`ref.read` 用于事件入口；`ref.listen` 用于状态转换触发的副作用。build 可声明监听，不直接发起写入、弹层或业务命令；需要布局后展示时延后到帧结束，并复查 mounted、当前对象和请求是否仍有效。

ProviderScope 覆盖保持 dependencies 完整，测试与弹层读取同一作用域。局部 Provider 身份由所属 ConsumerState 持有；autoDispose、ref.onDispose 与 ref.onCancel 按实际寿命处理，避免全局实例状态表。根页面保活不等于其中动画永久运行。

## 命令与异步

命令校验对象存在性、身份和当前状态，明确区分无效动作、内存已生效与保存失败。连续点击仍由业务身份和状态机保证幂等；界面请求锁仅避免重复弹层，不能代替业务校验。

Future 返回后检查 mounted 和请求身份；新请求取代旧请求时旧结果不能覆盖新状态。订阅、Timer 和 Controller 都必须有唯一释放方。控制器监听由 Provider 撤销，Widget 释放自己创建的控制器；外部传入的控制器由外部拥有。

## 事件与动画

从明确动作或状态转换生成局部反馈身份，不以“当前已完成”作为每次 build 的播放条件。完成使用会话/阶段身份，打卡使用本次操作身份；保存重试、主题切换、读取历史、返回和普通重建不产生新反馈。

不可见或减少动态效果时直接呈现最终结果；已经错过的反馈不排队补播。中途撤销、暂停或更换对象时取消旧动画并承接新状态。具体体验见 [动效](../product/motion.md)，运行条件见 [运行时](runtime.md)。
