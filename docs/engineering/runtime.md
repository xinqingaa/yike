# 运行时与性能

## 启动与导航寿命

AppStartup 等待存储初始化后提供 AppPrefs 作用域；失败保留文件并显示重试。Bootstrap 只负责冷启动展示与进入根页面，不人为延时。从后台返回或打开设置不重新初始化业务，不重复播放启动。

根页面保留本次打开的选择与滚动。页面栈覆盖、根 Tab 隐藏和应用进入非前台时，局部装饰动画停止；再次可见按当前业务状态定位，不补播过去的秒数、打卡或完成反馈。TickerMode 与生命周期、路由可见性共同控制绘制，不能只凭 Widget 仍 mounted 判断可见。

## 时间职责

业务时钟通过 clockProvider 注入，以真实经过时间计算有效用时；250ms pulse 是校准与到点处理机会，不是累计秒数来源。暂停不累计，到点封顶，阶段转换和幂等结算由 FocusEngine 与命令完成。

表盘绘制使用局部 Ticker 从当前会话时间锚点求连续进度。读数按秒变化，绘制可以按屏幕帧更新；每帧不提交业务快照、不结算、不写盘。减少动态效果时关闭装饰 Ticker，正常业务 pulse 与读数继续。

后台返回先校准当前会话，跳到真实进度，不逐帧补演隐藏时间。冷进程恢复仍按最后保存点暂停，不补算关闭期间。改变检查点频率、系统时钟调整处理或后台执行承诺属于单独产品决策；本轮维持既有恢复策略。

## 动画与资源寿命

控制器由创建它的 State 释放；监听在 Provider/State 对应清理入口撤销。使用共享输入驱动水面两份读数，避免独立时钟产生不同相位。缩略预览和启动品牌图保持静态。

静态原稿、动态进度和文字分层；可用 RepaintBoundary 隔离持续绘制，避免重建根页面或重算历史。缓存只保存可由输入重建的几何或资源，主题/尺寸变化使其失效。图片预热应解决实际首次使用闪烁，不无条件预解码整套大资源。

## 测量与预算

性能结论来自原生 profile 的 frame timing，分别检查 UI 和 raster；60Hz 的帧间隔约 16.7ms，120Hz 约 8.3ms。记录设备、构建模式、场景、样本量、分位耗时和长帧，不以模拟器 debug 流畅感或平均 FPS 代替。

重点场景是水位裁切与反色读数、日影蒙版、主题过渡、玻璃弹层及长记录列表。检查静止时无持续装饰帧、隐藏时 Ticker 停止，避免不必要的 saveLayer、全页模糊和重复语义。无法取得真机时明确保留该验证边界。

大历史数据检查初始化耗时、快照大小、同步序列化、统计查询与滚动开销；有测量依据再做索引、分页、缓存或存储拆分。验证方法见 [测试](testing.md)。

## 动效更新与事件时点

表盘 Ticker 只更新局部 DialFrame；数字按秒更新，静态资源子树与连续绘制分离。MotionGate 的渲染可见性用于停止 Ticker，实时 activeNow 判定用于一次性事件，防止多次状态提交合并到同一帧后误判来源。完成适配监听已接受的业务状态，帧投影到零不承担结算。

应用级未保存提示由 UnsavedStatus 唯一持有 AppPop 句柄，通过帧后复查协调展示/关闭。AppPop 的模态深度覆盖嵌套和实际 dismissed 生命周期；Toast 与状态浮层不计入模态深度，不停止业务计时。
