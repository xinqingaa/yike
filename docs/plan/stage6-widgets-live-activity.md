## 目标与范围

提供 iOS 主屏 / 锁屏小部件、汇总实时活动及动态岛，提供 Android 桌面小部件，使用户在应用外查看专注与今日打卡进度，并在安全能力允许时暂停 / 继续已有会话。

保留主应用 iOS 15.0 基线；扩展按系统能力降级。包含机械、水位、日影三主题的原生轻量表达与可访问性。暂不包含服务端推送更新、后台常驻服务、外部开始 / 结束 / 放弃 / 打卡、iPadOS 专项交互、macOS 小部件、Android 动态取色及计时恢复策略变更。

## 平台能力与降级

2026-10-25 已只读核对 Apple 的 ActivityKit、WidgetKit、交互组件及有界时间文本官方说明。平台事实与本项目采取的降级分开记录；具体设备行为在末尾集中核验。

| 系统能力 | 本阶段接入与降级 |
| --- | --- |
| iOS 15 | 主屏小部件可用；无锁屏组件、实时活动或原生交互按钮。时间显示须使用可安全封顶的方式；无法有界自动推进时显示带更新时间的静态读数，不用会越过零点的文本伪装实时计时 |
| iOS 16 | 增加锁屏组件；有界系统时间文本可按锚点推进并冻结 / 封顶；交互仍以打开应用为主 |
| iOS 16.1 起 | ActivityKit 实时活动及支持设备上的动态岛；没有动态岛的设备仍可显示锁屏实时活动 |
| iOS 17 起 | 可接 App Intent 按钮；`LiveActivityIntent` 能进入应用进程，但这不代表 Flutter 业务作用域已经就绪。仅在唯一业务写入者可安全调用时直接执行，否则回应用 |
| WidgetKit 时间线 | 可预先提交已知到点、优先模式变化及日期边界的展示条目，并在事实变化时请求 reload；系统预算、合并和短间隔限制意味着不能保证到点立即换行或每分钟重绘 |
| Live Activity 更新 | 不使用 Widget 时间线。系统时间文本可以自己推进，模式选择、文案、结束仍需应用获得执行机会；`staleDate` 只表达过时，不是定时执行或自动结束机制 |
| Live Activity 寿命 | 平台活动最长约 8 小时，结束后锁屏最多另留约 4 小时；本产品请求的完成结果保留约 5 分钟处于系统上限内。长时间暂停不能保证无限保留，也不承诺系统移除后后台自动重建 |
| Android RemoteViews | 尺寸按宿主实际 dp 约束适配，网格名是目标规格；事件变化时主动提交，周期更新受平台限制。不得把 `updatePeriodMillis` 或 WorkManager 当作每分钟 / 每秒精确定时器 |

Android 若使用系统 Chronometer，必须核对零点 / 上限后的行为；无法保证不出现负倒计时或超过 59:59 时，保留有更新时间的安全静态读数。不得通过新增常驻服务、精确轮询或后台第二套状态机换取实时读数。

### iOS 小部件

| 类型 | 尺寸 | 内容 | 点击与动作 |
| --- | --- | --- | --- |
| 专注进度 | Small | 按 R2 选出的模式、时间、运行 / 暂停状态；优先保证读数 | 整体进入该模式；只读 |
| 专注进度 | Medium / Large | 最多三模式的时间、状态、进度，空间允许时展示番茄轮次 / 正计时圈数及今日总时长 | 支持分区点击的尺寸逐行定位；安全能力允许时每行最多暂停 / 继续 |

| 今日打卡 | Medium | 今日 N/M、进度与按原顺序的前三项习惯及完成状态 | 整体进入打卡页，支持分区点击时定位对应习惯；不打卡 |
| 锁屏打卡 | Circular | 今日打卡进度环、完成数；0 个习惯不绘制虚假完成环 | 进入打卡页 |

三模式完整列表使用固定番茄 → 正计时 → 倒计时顺序保持位置稳定；R2 的最近到点排序只决定单模式展示目标。全部无运行 / 暂停会话时显示专注空态并进入专注根页；不新增外部开始按钮。没有进行中习惯时展示空态，不能把初始化失败呈现为 N=0、M=0。

### 汇总实时活动与动态岛

- 任一模式开始后创建 / 更新同一张汇总活动，后续会话加入，不为每个模式创建独立活动；系统拒绝启动时保留应用正常计时。
- 锁屏最多三行，包含模式 / 阶段、时间、进度、状态；每行最多暂停 / 继续。番茄休息明确标识为休息，不累计成专注时长。
- 动态岛 Compact Leading 为 R2 目标图标，Compact Trailing 为对应时间；正计时显示已用，倒计时 / 番茄显示剩余，全部暂停表达暂停。Minimal 在空间允许范围保留目标模式 / 状态语义。
- Expanded 最多三行及各自操作；受系统高度限制时缩减次要说明，不交叉绑定会话。内容导航和按钮点击分开。
- 暂停冻结读数并保留活动；某模式完成后下一次可提交更新时切到其它运行模式，全部运行态消失才选暂停态。所有模式自然完成后提交最终状态并调用结束，锁屏请求保留约 5 分钟；清空全部会话则立即请求移除。
- 设置独立呈现应用开关、系统允许状态及不可用原因，普通通知权限 / 总开关不代替实时活动能力判断。关闭活动展示不暂停、不结算计时。

不把 4×2 默认退化为只显示一个模式。若最窄宿主约束下三行与触控仍不能兼容，先给出实际约束及可行选择，直接询问用户，不擅自改变已确认的三模式布局。

### 三主题与可访问性

三主题共享信息结构，导出轻量品牌色、材质和必要图标，不复制 Flutter 表盘动画或完整 TS 对象。浅深、系统单色 / 着色及锁屏材质下先保证文字和进度可读，尊重平台对显示的接管。

使用系统字体、等宽时间、受约束布局和足够触控区域；长习惯名截断但保留读屏全名。读屏描述包含模式、阶段、时间、状态和动作，不每秒强制播报。减少动态效果时不加入额外装饰动画。

## 数据与外部命令

### 唯一事实与投影协议

MMKV / AppPrefs 中的业务快照仍为唯一事实。新增共享容器只保存可重建的只读展示数据，扩展不得读取后覆盖整份 MMKV，也不得独立结算、补历史或改变习惯。

| 数据组 | 最小字段与约束 |
| --- | --- |
| 外壳 | 格式版本、重置代次、投影 revision、生成时间、对应本地日期 / 时区、数据可读状态与保存状态 |
| 专注 | 模式、会话 ID、阶段身份、状态、目标 / 量程 / 上限、累计有效用时、时间锚点、轮次 / 圈数、导航目标与允许动作 |
| 汇总 | 使用现有公开统计口径派生的今日时长；三模式独立累加、不去除重叠区间、不重复累计已结算记录与当前会话 |
| 习惯 | 全部进行中习惯的今日 N/M；前三项及第一项所需 ID、名称、图标、顺序和今日状态；日期过期不冒充今天 |
| 外观与能力 | 主题标识及必要颜色 / 资源引用；实时活动应用开关及平台可用能力，不与通知权限合并 |

应用层组合 feature 公开事实；`common` 的协议和平台适配器不反向依赖 feature。iOS 经 App Group 共享投影，Android 经应用私有展示存储交给 RemoteViews；平台负责原子替换与读取失败兜底，不新建业务存储后端。

共享投影在状态、习惯、配置、主题、日期、恢复和重置变化时更新，按语义内容去重；不随 250ms pulse 全量序列化，不依靠跨端每秒写入。保存失败时遵守内存已经生效的原规则，投影明确未保存状态；重试不重做暂停 / 继续。

### 外部目标与命令流

1. 接收类型化载荷，区分“查看”与“暂停 / 继续”；校验版本、动作白名单、模式、会话 / 阶段身份、重置代次和预期状态。内容点击不隐式变成操作。
2. 等待 AppPrefs、业务读取 / 恢复及唯一业务作用域就绪；同一串行入口消费命令，主应用和扩展不能并行写事实。不能安全进入时打开应用，不启动独立业务 isolate / 原生计时状态机绕过限制。
3. 执行前读取最新事实并校准到点，再核对身份及动作允许状态。过期动作不改投影里的另一会话；重复暂停 / 继续不能被实现成 toggle，重复投递不得反向操作。
4. 调用现有 `FocusActions.command`，必要时补充阶段与结果参数；明确区分拒绝、已接受未保存、已保存，平台展示更新失败另行表达。
5. 查看导航复用通知的根页 / 模式 / 习惯定位；先等通用模态安全退场，不静默丢草稿、不重复压根页。执行命令与导航等待分开，不能因为当前有模态就丢命令或反复执行。
6. 执行后发布最新共享投影并请求组件 / 活动更新；不重复业务声触、不回放旧完成效果。仅操作其它模式时保留原页面所选模式，进入应用处理的意图按目标定位。

### 生命周期与失效

- 回前台按真实时间校准全部会话，再发布共享投影和活动状态；冷进程仍从最后有效保存点恢复暂停，不补算关闭时间，不增加周期检查点。
- 应用异常终止时系统可能继续展示旧锚点。下一次冷启动先恢复，再覆盖全部原生投影并校准 / 撤销旧活动，不用补写历史掩盖差异。
- `staleDate`、日期变化与旧格式 / 读取失败只影响展示和操作可用性；失效时标识需要打开应用更新，禁用旧动作，不虚构习惯未完成或专注结束事实。
- 读取受阻时不能导出 `YikeData.initial` 作为真实初始习惯；投影失效处理须位于读取失败分支也能执行的应用边界。
- 重置先使旧代次 / 外部命令失效，串行结束活动并清共享数据；旧异步写入不得重新发布重置前内容。新初始化成功后才发布新代次。
- 组件删除、系统活动拒绝 / 回收、权限关闭或平台更新失败不改变会话 / 统计；平台失败保留可重试状态，重试只对账展示。

### iOS 实时活动显示故障修复

交付后用户在 iPhone 17 / iOS 26.1 Simulator 反馈：番茄钟运行时动态岛不显示，macOS 反复弹出 `WidgetRenderer_Activities` 崩溃报告。诊断同时捕获 `YikeWidgets` 扩展与系统渲染器的 `SwiftUICore/Layout.swift:1535` 断言：`view origin is invalid: (nan, …)`。先前构建、共享文件与 ActivityKit 更新成功不能证明实时活动实际渲染成功，原有限抽查不足以覆盖该故障。

根因位于系统倒计时文字的布局约束：计时行对 `Text(timerInterval:)` 使用 `fixedSize()`，运行态在 WidgetKit 归档布局中不能给出有限理想宽度，使整行及进度条原点变成 NaN。暂停态使用静态文字，因此可以出现“暂停可见、运行后崩溃”。修复移除两处 `fixedSize()`，为列表 / 活动读数及动态岛紧凑读数指定有限宽度、单行和缩放；进度条显式使用 linear 样式、空标签与正常高度。保留有界系统倒计时与进度自动推进，没有新增业务时钟或退化成静态计时。

本轮仅补查该原生链路：模拟器安装修复版，使用真实业务命令运行番茄钟，系统界面操作并截图核对主屏动态岛 Compact、长按 Expanded 与通知中心活动；读数依次为 24:57 / 24:53 / 24:46，暂停图标和进度可见，确认后台系统读数确实推进。处理模拟器首次允许 / 持续允许活动的系统提示，未重置或清空用户数据。临时诊断应用及原生 UI 操作脚本放在仓库外，不增加生产测试入口；Flutter / Android 未修改，不重复全套 Dart 检查。最终 iOS Simulator debug 与 iOS device debug 签名构建通过；14:22:22 安装修复版至 14:31:00 的日志中，扩展 / 系统渲染未再出现 Fatal error，12 次活动归档批次成功。原生 UI 操作核对运行态内容可见，临时诊断应用与 UI runner 已从模拟器卸载，当前一刻安装及历史数据保留。文档检查通过；真机全矩阵仍按上述边界保留。

| 通用通知栏 / 锁屏持续通知 | 标准通知 API 支持 ongoing、计时显示、进度和点击入口；基础展示难度中等，不需要逐厂商 SDK，也不以常驻服务为发布前提。锁屏是否显示仍由权限、通知渠道、隐私和系统决定 | 技术上可做，不能称为 Android 完全无法打通；但它是新增能力，需要用户确认范围 |
| 严格封顶、暂停恢复、多模式与异常退出一致 | 难度较高。系统 Chronometer 到零后会继续输出负时间，正计时也不会自行停在 59:59；停止 / 换行 / 移除仍需应用执行。已有 AlarmManager 在没有精确权限或厂商延迟时不能保证准时更新，且提醒关闭不能让展示失去清理机会；冷进程恢复暂停时也需撤销旧展示 | 不能仅把 TextView 换为 Chronometer 就交付。需要独立处理展示寿命、到点刷新、身份校验、通知设置及清理，不新增原生业务结算 |
| Android 16 增强持续通知 | 平台有 promoted ongoing 能力，但格式合格不等于系统一定提升展示；跨系统外观与能力仍有差异。本次尚未验证当前机型对本产品场景的提升效果 | 不作为本轮依赖，也不承诺获得等同 iOS 的系统入口 |
| 小米超级岛及其他厂商专有入口 | 引入厂商能力、接入条件和额外维护面；与通用锁屏通知是不同目标 | 用户已明确排除，不接入、不继续开展专项适配 |

**综合建议：本轮只修复 Android 桌面组件的布局和尺寸，Android 锁屏继续保留当前到点提醒。** 原因是收益与维护成本的取舍，而非已经证明 Android 无法实现。用户随后已批准该范围；将来若选择新增通用持续通知，应另明确可接受的时间封顶 / 后台延迟边界，不能自动扩展为常驻服务或放宽既有恢复规则。
