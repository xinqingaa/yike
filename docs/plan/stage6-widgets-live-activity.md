### 已能确定的逻辑约束

- 下文的“每分钟刷新”“暂停 / 完成立即刷新”改为更新目标，不是系统送达保证。系统可能延迟 / 合并刷新，不能依靠跨端每秒或每分钟写入证明计时正确；读数优先使用系统基于时间锚点的显示能力并在目标封顶，暂停冻结。
- 原生投影需要展示身份、状态、时间锚点、上限、更新时间和格式版本；过期、读取阻断、重置和身份失效时不可继续开放旧按钮或虚构未完成习惯。只读投影不反写为第二份事实。
- 冷进程恢复仍遵守第五阶段“最后保存点暂停、不补算关闭时间”。系统无法保证异常终止时立即通知 Widget / 实时活动，因此旧活动可能暂时继续按原锚点显示；冷启动恢复后必须同步全部原生投影并暂停 / 撤销旧活动。该既有平台边界不通过补写历史来掩盖，不承诺应用被杀后始终精确反映暂停。
- 外部命令必须再次检查模式、会话 / 阶段身份和预期状态，串行交给唯一写入路径；扩展不能基于上次展示内容读改写整份 MMKV。平台无法唤起安全业务运行环境时回应用处理，不采用独立的原生会话状态机。
- 任何系统拒绝启动活动、版本不支持、刷新延迟和组件移除，只影响展示 / 操作入口，不改变计时、统计或习惯事实。普通通知开关不等同于 Widget / Live Activity 授权；能力按各自系统入口处理，不因一项关闭而误报其它都不可用。

## 产品设计

### iOS 小部件

**位置与尺寸**:

- **主屏幕**: Small (正方形)、Medium (横长)、Large (大)
- **锁屏**: Circular (圆形)、Rectangular (矩形条)、Inline (单行文字)

**内容**:

| 类型 | 内容 | 刷新 |
| --- | --- | --- |
| 专注进度 (Medium/Large) | 当前模式、轮次/圈数、倒计时/正计时、今日总时长 | 计时中每分钟,暂停/完成时立即 |
| 今日打卡 (Small/Medium) | 今日完成 N/M、进行中习惯列表（最多 3 个） | 打卡时立即 |
| 锁屏圆形 (Circular) | 今日打卡进度环形图,中心显示完成数 | 打卡时立即 |
| 锁屏矩形 (Rectangular) | 当前专注倒计时或"已暂停" | 计时中每分钟 |

表内刷新频率是展示更新目标，受系统预算限制；小尺寸专注内容按 R2 选择模式。正常暂停 / 完成会主动提交新投影，不保证系统立刻重绘。

点击小部件跳转到应用对应页面（专注或打卡）。

### iOS 实时活动（Live Activity）

**触发**：任一模式开始后更新同一张汇总活动，纳入番茄专注 / 休息、正计时、倒计时。暂停保留，某模式完成后优先展示其它运行模式；全部完成 / 清除后结束，不自动开始下一阶段。

**锁屏示意（至多三行，每行最多暂停 / 继续）**:

```
[图标] 番茄钟 第 2 轮    18:32  暂停
━━━━━━━━━━━━━━━━━━━━
[图标] 正计时          12:34  暂停
━━━━━━━━━━━━━━━━━━━━
[图标] 倒计时 · 已暂停  03:20  继续
━━━━━━━━━━━━━━━━━━━━
```

**动态岛样式**:

- **Compact Leading**: 最近到点的运行模式图标；番茄可带轮次
- **Compact Trailing**: 对应模式 mm:ss，正计时显示已用时间；全部暂停显示暂停状态
- **Expanded**: 至多三行模式、进度条和时间；每行最多一个暂停 / 继续按钮，按实际系统空间降级

**显示目标**：秒级倒计时；优先使用系统时间展示能力，具体刷新机制与平台限制在启动时核对，不承诺每秒跨端写入。

### Android 小部件

**尺寸**: 2x2 (小)、4x2 (中)、4x4 (大)

**内容**:

| 类型 | 内容 | 刷新 |
| --- | --- | --- |
| 专注进度 (4x2) | 模式、时间、暂停/继续按钮 | 计时中每分钟 |
| 今日打卡 (2x2) | 完成数 + 第一个习惯的图标和名称 | 打卡时立即 |
| 今日打卡 (4x2) | 完成进度条 + 前 3 个习惯列表 | 打卡时立即 |

4x4 可承载三模式完整预览，4x2 按可读性保留汇总或当前优先模式；具体约束布局由原生尺寸验证确定，不新增业务模式。刷新同样受系统预算限制。

点击小部件进入对应页面；暂停 / 继续仅在平台能够安全调用统一业务命令时直接执行，否则打开应用完成同一意图。

## 工程方向与启动边界

原方案拟手写 Swift / WidgetKit 实现 iOS 主屏及锁屏组件，评估 live_activities 与原生桥接实现实时活动和 Android RemoteViews。包版本、能力、系统最低要求、App Group、签名与后台限制在对应准备工作中核对；本次计划修订不添加依赖或扩展工程，不限制后续在第五阶段期间独立准备本阶段原生工程。

MMKV / AppPrefs 业务快照仍是唯一事实源。原生共享容器只保存展示投影，含会话身份、固定目标与量程、时间锚点、状态及今日汇总；原生按钮通过统一命令校验当前会话，不能直接写独立计时或打卡事实。主题共享内容须轻量，并支持数据缺失、未初始化或读取阻断。

三主题复用结构，按品牌色和材质调整；小尺寸保留时间 / 状态与清晰语义，不堆完整应用布局。点击进入对应根页，外部只允许暂停 / 继续，后台执行能力和权限由原生接入时核对；不引入外部短记录确认。系统刷新预算与应用异常终止恢复不得形成两套计时口径。

实施顺序：核对平台版本，按 R2 / R3 固定布局与操作边界；配置原生扩展与共享投影；接统一深链 / 命令；接会话和习惯更新；集中验证尺寸、锁屏 / 动态岛、暂停完成、数据失效及系统回收；由用户真机验收。模拟器结果不代替后台可靠性或耗电测量。
