状态：2026-10-25 用户确认功能与逻辑验收通过；临时验收材料已清理，长期回归保留。用户另提出站内提示与通知设置的 UI 优化，本轮只整理计划，尚未实施。返回 [计划索引](README.md)。

## 已明确的范围

- 去除三个模式互斥：番茄钟、正计时、倒计时可以同时存在并独立计时。切换模式是查看另一模式，不再结束、放弃或自动暂停原模式。
- 通知分为前台站内状态展示与后台系统本地通知。前台展示不依赖系统通知权限和后台提醒开关。
- 离开对应计时页面后，顶部用半透明玻璃容器预览其状态；三个同时运行、且都不在当前查看页面时显示三行。每种模式统一使用长进度条，点击回到对应模式。
- 状态条以预览为主，每行最多增加一个暂停 / 继续操作。不放结束、放弃、计圈、再计或开始休息等操作。
- 前台只播放当前查看模式的计时声音与触感；切到打卡、回顾、设置等非计时页面时，所有计时反馈静默，不采用三路声音合并。本模式计圈面板仍属于本模式，通用设置 / 编辑 / 确认层静默；恢复可见不补播。
- 统计沿用各模式已入账记录相加的口径：三模式各记录 10 分钟，统计总计 30 分钟；这只解释统计结果，不改变各自计时。此项已确认，没有待决问题。
- 运行和暂停的站内状态条持续显示；完成时进度拉满、标记完成后自动退场，不常驻。完成态会话和必要的短记录确认仍留在对应页面，不随通知消失而清除。
- 不考虑旧数据兼容或迁移，直接使用新的三模式快照格式；用户自行卸载旧包或手动清理缓存，不由应用静默清空数据。
- 后台主体沿用原清单：计时到点、习惯提醒、本地通知权限、点击进入应用；不增加服务端推送、后台音频或依靠 Dart 常驻执行的方案。
- 既有 1–3599 秒上限、番茄轮次及休息、短记录确认、倒计时再计与正计时计圈规则沿用。改变一模式不得清除其它模式的会话、计圈或待处理结果。
- 真正冷进程重开仍从最后保存点恢复暂停，不补算关闭期间。通知预约不能替代业务结算，亦不能凭通知已送达就补记历史。
- 可自主选择必要验证，不频繁启动模拟器或反复全量测试；声音和震动最终由用户用 Android / iOS 真机验收。交付临时验收脚本与步骤，用户通过后才清理临时脚本、截图和交接材料，保留必要长期回归。

### 弹框库核对与工程建议

已只读核对本机安装的 unified_popups 2.2.1 及本地封装：`PopupHandle.pause()` 保留 Entry / Widget 状态但不绘制、不响应手势，`resume()` 恢复；Host 的 `Offstage` / `IgnorePointer` 实现与文档一致。`AppStatusPopup.suspend` 已封装该能力；`popupActivityProvider` 持续计数到实际 dismissed，能覆盖嵌套 Sheet / FlowSheet / Confirm / Loading，计圈面板也在该边界内。

- 站内状态采用一个应用级常驻展示宿主，内部最多三行，不分别创建三个 Toast。模态打开时挂起展示，最后一个模态真实退场后恢复最新投影，计时和预约不暂停。
- 若复用 `AppStatusPopup` 的自定义展示接口，先将其固定的 `yike-unsaved` 身份改为受控参数，为计时使用独立身份；不能直接复用未保存提示的同 key。业务层不持有 SDK 句柄。
- 顶部状态区域与页面内容避让统一协调，维持根 Navigator 的完整视口约束，不靠每秒重建根布局；未保存错误与计时区域须统一排布，不能互相遮挡。仅做局部尺寸 / 动画适配，像素参数由 UI 目视调整。
- 非模态数据卡不等同于模态，不单凭 Overlay 存在就隐藏状态条；跳转前由卡的拥有者关闭查看卡。通用模态深度只管状态条隐藏，计时反馈另识别模态所属用途：计圈面板允许正计时反馈，通用确认层覆盖后仍静默。

## 目标数据、命令与完成事件

### 三模式独立会话

1. 同一模式最多一个未清理会话，三个模式各占一个槽；番茄专注与休息仍是番茄槽的连续流程，不扩展成同模式多个计时器。
2. 会话继续拥有独立身份、模式、阶段、目标 / 量程、有效用时、锚点、日期分片、计圈和短记录待处理状态。番茄周期只由番茄命令改变。
3. 所选模式是展示状态；切换不结算、不清除完成态，不触发短记录确认。待开始草稿按模式保留，设置变更只影响未开始目标。
4. 动作用 `mode + expectedSessionId` 校验；休息转换、再计和重新开始均生成新身份。旧状态条、旧通知或异步确认不能操作新会话。
5. 同一时刻采样所有运行会话，原子提交组合结果。按身份幂等入账，批量生成完成事件；三路同秒完成不能覆盖、漏发或重复增加轮数。
6. 异步确认返回后再次检查模式、原会话和请求身份。确认某模式的短记录只冻结该模式，其它模式继续。
7. 完成态仍等待原页面处理，不从站内条或系统通知自动开始休息 / 下一轮、不自动确认短记录。非当前模式完成时的提示延迟至回到该模式，模态期间同理，不抢焦点。
8. 冷启动对所有保存的运行态恢复暂停，原已暂停 / 已完成态各自保留。冷启动先显示番茄钟，不保存最近查看模式。恢复选项在进入对应模式时处理，一次只处理该模式，不连续强弹三份面板或替用户继续所有会话。

### 存储与兼容

- 在同一 `business_snapshot` 内保存三个槽和后台提醒总偏好，不为每模式创建独立业务数据库。
- 快照升至版本 3，直接采用三模式结构，不读取或迁移版本 2 / 更早结构，不实现兼容字段。用户自行卸载或清理缓存；应用不自动清空不支持的数据。保留新格式重复模式 / 身份、目标范围、损坏和未知版本校验，新增通知总开关默认关闭。
- 预约 ID、代次及习惯日期的已消耗提醒机会属于调度元数据，不是业务完成事实。是否放在专门快照字段或独立类型化 AppPrefs 项由适配实现决定；新增 key 前登记存储文档，不写第二份可独立变动的会话数据。
- 内存接受、保存成功、系统预约成功分别表达。保存失败不重做命令；调度失败单独可见、可重试，不显示成业务失败。保存重试不重播反馈、不补发过时提醒。

## 前台站内状态条

按已确认的 D1 / D2 实施，字段和读数如下：

| 模式 / 阶段 | 预览示例 | 长进度条 | 额外操作 |
| --- | --- | --- | --- |
| 番茄专注运行 | 番茄钟 · 第 2 轮 · 剩余 18:32 | 本阶段有效用时 / 固定目标 | 暂停 |
| 番茄短休 / 长休 | 短休 · 剩余 00:21 / 长休 · 剩余 12:00 | 当前休息的完成比例 | 暂停 |
| 正计时运行 | 正计时 · 已用 12:34 | 已用时 / 59:59 | 暂停 |
| 倒计时运行 | 倒计时 · 剩余 03:20 | 有效用时 / 实际固定目标 | 暂停 |
| 任意模式暂停 | 模式 / 阶段 · 已暂停 · 当前时间 | 冻结原比例 | 继续 |
| 任意模式完成 | 模式 / 阶段 · 已完成 / 待确认记录，辅以小勾标记 | 拉满后短停留并自动退场 | 停留阶段可点整行返回，无额外按钮 |

三种模式统一用从空到满的完成比例，不拿常用项量程替代本次目标。读数派生自同一会话，不自行累计秒数。

组合位置放在应用层，覆盖根 Tab 及设置 / 统计 / 习惯详情等栈页面，不在各页面复制。可见性包含根 Tab、路由和当前模式，不能仅看 mounted。任何模态期间整个状态条隐藏且不可交互；最后一层退场后恢复，业务计时不受影响。系统通知点击在应用就绪、模态安全退场后处理，不能静默丢弃未提交表单。状态条对非当前模式的暂停 / 继续同样遵守 D4，命令有效但不另发计时反馈。

复用 `CommonGlassSurface`、公开进度条和主题量；三主题共享结构，浅深及高对比度可读。读屏提供模式、阶段、时间、状态和操作，不每秒强制播报。局部更新读数与进度，非前台停止装饰动画；减少动态效果时直接定位，不延迟业务变化。

### 状态条动效与寿命

完成条不再常驻。以下为用户允许自主调整的首版时序，实施后用 UI 过程验收微调；参数集中在类型化动效 Token，不在 Widget 内散落常量。

| 变化 | 初始时序与过程 | 中断与连续性 |
| --- | --- | --- |
| 新增 / 从计时模式离开 | 约 240ms，行高度展开并小幅下移淡入；玻璃容器边界和页面避让同步过渡 | 仅新增行入场，已有行保持身份；当前时间直接取真实投影，不从零演一遍 |
| 暂停 / 继续 | 约 160ms 切换标签 / 图标，保留行高和冻结进度，继续后从当前位置推进 | 不退出再重新入场；反馈命令立即生效，不等动画 |
| 自然完成 | 约 180ms 将最后一段平滑收满，标签换为“已完成”并淡入小勾；完整状态停留 800ms，再用约 220ms 淡出 / 向上收起 | 总体约 1200ms；不闪烁、跳色或循环庆祝，不额外加声音 / 触感；停留时可点返回，退场开始立即移除触摸 / 焦点 / 语义 |
| 删除一行 / 多行同时完成 | 行透明度、可见高度和邻行位置共同过渡；同时完成的行在同一布局事务中收起 | 不串成三次弹跳，不重放其它行入场；最后一行消失时连同玻璃外壳和顶部避让一起收起 |
| 点击返回 / 切换模式 | 同步根导航 / 模式转场和状态条集合变化，约 240ms 连续换位与尺寸过渡 | 被进入的模式条退场，离开的运行 / 暂停模式按当前进度入列；不等条退完才导航，不使用表盘到状态条的跨布局飞行动画 |
| 模态打开 / 关闭 | 打开即屏蔽状态条交互和语义，约 160ms 跟随遮罩淡出，然后挂起；最后一层实际退场后按最新集合约 200ms 恢复 | 不能只调用库 pause / resume 导致瞬间消失 / 闪现。库负责保活与屏蔽，本地呈现控制器负责过渡；快速开关从当前画面接续 |
| 主题 / 大字体 / 窄屏变化 | 保留同一行和展示阶段，材质按主题规则插值，尺寸按新约束连续变化 | 不以重建当作完成事件，不重置停留时长；时间及操作不能在插值中被裁掉 |

- 完成反馈只消费“当时已经可见的运行行自然到点”事件，以会话 / 阶段身份去重。当前模式主页面完成时不额外创建状态条；模态、后台或隐藏期间错过的完成不排队补播。完成条一旦隐藏或超时就消耗此次展示资格，返回 / 再切换不能重新常驻；业务完成态仍可通过专注页模式 Tab 处理。
- 完成停留和过期使用单调的展示时间基准，不依赖设备墙上时钟；页面重建、保存重试、主题变更不能重新计时。再计或进入休息是新会话 / 阶段，拥有新的展示身份。
- 约 1200ms 是短暂视觉提示，不是必须在其中完成点击的唯一操作入口；原页面继续保留完整处理动作。辅助语义提供一次完成状态变化，不强制每秒播报。
- 新事件中断过渡时从当前高度、透明度和位置继续，退场后又出现的新运行身份不能复用旧计时器。动画控制器 / 超时任务按展示宿主释放，后台不保留装饰 Ticker，不能等待 `dismissed` 才更新业务。
- 减少动态效果时取消移动、缩放和进度补间，直接显示满条与完成标记，保留相同的短停留后直接移除；运行 / 暂停的事实与可操作性不变。其它行不随列表更新整组重播。

## 前台计时反馈门控

| 用户所在位置 | 允许的计时声音 / 触感 | 状态条 |
| --- | --- | --- |
| 番茄页面 | 仅已启动的番茄（含其休息阶段） | 另两模式的运行 / 暂停条及尚未退场的完成条 |
| 正计时页面 | 仅已启动的正计时 | 另两模式的运行 / 暂停条及尚未退场的完成条 |
| 倒计时页面 | 仅已启动的倒计时 | 另两模式的运行 / 暂停条及尚未退场的完成条 |
| 打卡 / 回顾 / 设置 / 详情 / 统计 | 所有计时反馈静默 | 最多三行 |
| 本模式计圈面板 | 仅所属正计时；仍按本模式开关 | 隐藏，不可交互 |
| 通用设置 / 编辑 / 确认 / Loading 等模态 | 所有计时反馈静默，包含覆盖在计圈之上的确认 | 隐藏至最后一层真实退场 |

“当前模式”由展示上下文决定，不能用最近开始的会话或仅 `FocusData.mode` 代替；计时反馈也不因仅剩一个运行模式就绕过该门控。模式隐藏时立即停止其现有音频和未触发的第二次强触，恢复仅建立当前有效时间基线。到点、保存及完成事件照常提交，静默不丢业务结果，也不排队等用户返回才播放。

打卡、查看卡触感、显式试听仍按各自已确认规则处理，不能误用计时可见性关闭整个服务。统一服务只接收类型化来源 / 允许状态，页面与模态用途的判断留应用组合和 focus 协调层，不反向引入 feature 依赖。

## 后台通知与调度

### 习惯提醒的最终范围与开关

用户已确认前台静默站内提示与后台系统本地通知同时接入第五阶段。当前已接入权限、预约、到点处理、取消 / 重排、去重与点击定位。全部在本机完成，不增加服务端、账号或联网推送。

| 条件 | 前台习惯站内提示 | 后台 / 锁屏习惯系统通知 |
| --- | --- | --- |
| 进行中、提醒开启、今日未打卡、到点机会未消耗 | 约 3 秒静默提示，点击定位；有模态则跳过、不补发 | 后台总开关开启、系统允许且预约成功时送达；点击定位、不自动打卡 |
| 后台总开关关闭或系统通知权限拒绝 / 撤销 | 仍可提示，只受习惯自身开关及上述业务条件控制 | 不发送；显示后台不可用原因，不自动修改习惯开关 |
| 习惯提醒关闭、归档、删除或今日已打卡 | 不提示 | 取消对应未来预约；删除另清理已送达内容 |

前台与后台按同一习惯身份及本地日期共享一次机会；切换前后台不能重新提醒。前台到点判断复用可注入时钟、生命周期和最新习惯事实，不依赖系统送达回调，因此拒绝系统权限或未排入 iOS 队列也不影响前台提示。回前台不补发已错过的提醒；到点时处于模态也不延后展示。

### 场景与内容

| 场景 | 触发条件 | 标题 / 正文 | 点击结果 |
| --- | --- | --- | --- |
| 番茄专注完成 | 有效目标到点，应用不在前台，后台提醒有效 | 番茄钟完成 / 本轮 {目标时长} 已完成 | 专注根 Tab → 番茄，显示真实结果 |
| 倒计时完成 | 同上 | 倒计时完成 / {目标时长} 时间到 | 专注根 Tab → 倒计时，显示真实状态 |
| 正计时上限 | 到达 59:59 | 正计时完成 / 本次计时已达到 59:59 | 正计时，保留计圈与完成态 |
| 短休 / 长休完成 | 当前休息目标到点 | 休息结束 / 可以准备下一轮了 | 番茄，仍等待用户准备下一轮 |
| 习惯提醒 | 预约日期及时刻，进行中、开启提醒、当天未完成；后台系统通知，前台约 3 秒静默提示 | {习惯名称} / 今日尚未完成 | 打卡根 Tab → 定位习惯，不自动打卡 |

旧草案“点击后待开始”改为读取真实状态；导航不能清理会话、结算、重置或替用户开始任务。冷启动仍按既有恢复策略；旧会话通知只定位对应模式，不操作新会话；习惯失效返回打卡并说明，不虚构记录。

### 预约与前后台交接

- **计时预约**：开始 / 继续时即根据固定结束锚点准备预约，避免等待后台回调造成窗口丢失。暂停、结束、放弃、阶段转换及再计取消旧预约；继续按剩余有效时长重建，三模式互不取消。
- **前台抑制**：计时及习惯系统送达入口在应用前台时抑制系统横幅、声音和震动，由现有反馈服务和计时站内条负责。习惯按已确认 R1 由本地到点判断显示约 3 秒静默短提示，不能直接套用计时条或依赖系统通知回调而漏掉提醒；两路共用提醒身份去重。iOS 核对 delegate 展示选项；Android 核对 scheduled receiver 的抑制能力，必要时加最小原生接收桥，不能只靠 Dart 回前台取消来声称无竞态。
- **统一校准**：回前台先静默校准所有会话，再对账预约，最后建立各模式节拍基线。边界同秒不重复通知或补播，后台没有执行 Dart 也能显示最新投影。
- **习惯联动**：打卡取消当日预约；取消 / 有效撤销按 D8 决定是否重排；编辑名称、提醒时间、开关和频率对账；归档取消全部待发，恢复按事实重排；删除清理 pending + delivered。已完成不提醒依靠预约前检查和变更时取消，不假设 iOS 送达时会唤醒 Dart 查询。
- **全局变化**：按 D5 处理开关；重新获权、启动 / 回前台、跨日、时区 / 夏令时变化时重建未来日历预约，过去不补发。设备重启 / 应用升级核对原生 receiver 的重建行为，强制停止与进程回收分别记录。
- **进程结束**：系统预约可能继续送达，冷重开仍恢复暂停；可能出现“系统提醒时间到，应用恢复最后保存进度”。不能可靠侦测所有异常终止并即时撤销；不新增常驻服务或暗改恢复规则。冷重开清理旧计时预约后以恢复态对账。
- **一致性**：从最新事实生成期望集合，与 pending / delivered 对账；异步串行执行并携带代次，旧回调不能覆盖新取消。ID 稳定且无碰撞，payload 只放类型、模式 / 习惯身份、会话 / 阶段及日期，不放完整快照。
- **容量（D10）**：按全应用预算分配，不能依赖超额后的保留顺序；计时优先，习惯按最近日期排序。覆盖范围必须来自实际成功预约的请求；不同习惯覆盖不同时，显示各自范围 / 未排入数，总体不能用最远日期冒充所有习惯都覆盖至该日。不能无限一次性预约，不能用无条件重复冒充“已完成不提醒”。

### 权限、设置与平台核对

- 设置页“记录与反馈”增加“通知提醒”，默认关闭；开启时请求权限，习惯自身开关和时刻保留。用户开启习惯提醒不自动打开后台总开关或申请系统权限；若后台未开启 / 未获权，明确说明“前台可提醒，后台未开启”，并提供后台设置入口。前台不新增总开关。
- 应用偏好和系统授权分别显示；拒绝 / 撤销后不反复弹框，提供系统设置入口。通知权限、Android 精确授权、渠道禁用、系统专注 / 静音不是同一状态。
- 当前锁定 `flutter_local_notifications` 22.3.2、`flutter_timezone` 5.1.1、`timezone` 0.11.2；本机 Flutter 3.44.8 / Dart 3.12.2。Android 开启 desugaring 并通过自有原生桥调度以保证发布前前台抑制；iOS 不提升 15.0 部署目标。
- iOS 当前部署目标 15.0；Android compile / min / target SDK 由 Flutter 工具链给定，不能把占位表达式当作确定版本。核对 Java / Gradle、desugaring、小图标、权限和 receiver；本阶段不为实时活动提高最低版本或创建 Widget 扩展。
- 日历提醒明确设备时区来源及 timezone 初始化；计时按剩余持续时间，习惯按本地时刻。时区不可用、预约失败和权限变化可观察，不能假报开启成功。
- 按 D9 转换平台可用音频。Android channel 的声音 / 震动创建后受系统管理；主题 / 偏好变化采用有限稳定渠道方案，不每次新建、不覆盖用户系统设置。iOS 普通本地通知没有独立触感编排接口。

## 验证与用户验收
