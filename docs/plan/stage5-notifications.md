## 产品设计

### 通知场景

| 场景 | 触发 | 标题 | 正文 | 点击目标 |
| --- | --- | --- | --- | --- |
| 番茄钟完成 | 倒计时到 0 且应用不可见 | "番茄钟完成" | "本轮 {目标时长} 已完成" | 专注页待开始下一轮 |
| 倒计时完成 | 倒计时到 0 且应用不可见 | "倒计时完成" | "{mm}:{ss} 时间到" | 专注页待开始倒计时 |
| 习惯提醒 | 到达设定时间且未完成 | "{习惯名称}" | "今日尚未完成" | 打卡页对应习惯 |

前后台状态沿用应用级生命周期边界，平台送达策略在本阶段核对。

原草案要求后台通知、前台不展示系统横幅；具体预约与前后台切换由启动本阶段时核对。

### 习惯提醒规则

- **每日一次**:每个习惯每天最多提醒一次,到时间后检查今日是否已打卡。
- **已完成不提醒**:打卡后取消该习惯当日的待发通知。
- **归档取消**:归档习惯立即取消其所有待发通知。
- **删除清理**:删除习惯清理其所有历史通知（pending + delivered）。
- **编辑更新**:修改提醒时间或关闭提醒时,取消旧的,按新设置调度。

### 通知设置

在设置页“记录与反馈”区块增加一项:

```
通知提醒  [开关]   -- 控制所有后台通知（计时 + 习惯）
```

默认**关闭**。开启时请求权限,关闭时保留权限但不调度新通知（已调度的不主动取消）。

拟使用 flutter_local_notifications；版本、SDK / 平台要求与权限 API 在启动时核对，不把草案包版本视为已批准安装。计时预约与会话身份、目标结束点关联，暂停、继续、放弃及结束同步取消或重建；习惯编辑、打卡、归档与删除同步调度。通知点击通过路由与公开命令进入对应页面，不创建第二份业务数据。

主题完成音按系统支持转换到原生资源；系统权限、静音、渠道和调度限制需分别说明，送达不承诺精确到秒。申请权限由用户开启相关能力触发，拒绝后展示系统未开启，不循环请求。

原草案中的“仅后台调度”、关闭总开关保留已预约通知、通知点击直接待开始等行为，需在启动时与会话完成态、恢复策略和系统约束一起确认；本次不擅自决定。正计时 59:59 与休息完成的通知范围亦在本阶段确认。
