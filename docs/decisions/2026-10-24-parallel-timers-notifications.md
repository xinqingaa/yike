# 三模式并行与前后台提醒

日期：2026-10-24。状态：用户已确认第五阶段全部产品组合，计划定稿、代码尚未实施；详细范围见 [第五阶段计划](../plan/stage5-notifications.md)。

## 已决定

- 番茄钟、正计时、倒计时可并行，去除模式互斥与切换时必须结束 / 放弃原会话的要求。切换只改变查看模式，其它会话继续保持原状态。
- 提醒分为前台站内状态与后台本地通知；后台覆盖计时到点及习惯提醒。用户最终确认习惯采用“前台静默站内提示＋后台系统本地通知”，完整本地提醒链路纳入第五阶段，不增加联网推送。
- 离开某计时模式页面后，顶部以半透明玻璃容器预览状态；三个同时进行时，在其它页面可以显示三行。全部模式采用长进度条，点击进入对应模式。
- 前台以预览为主，每行最多提供一个暂停 / 继续操作，不扩展结束、放弃、计圈等动作。
- 状态条仅列非当前模式，运行 / 暂停持续保留；用户后续修订为完成条拉满进度、显示小完成样式后自动退场，不常驻。首版约 180ms 收满、800ms 停留、220ms 退场，整体约 1200ms；隐藏 / 超时后不因导航重现，业务完成态仍在原模式。行增减、模式转场、收展、多行同时完成和模态交接须连续承接，细则同步动效文档。
- 整行返回，运行 / 暂停额外一个暂停 / 继续按钮，完成条停留时可返回，退场开始失去交互。顺序固定番茄、正计时、倒计时。
- 所有模态打开时隐藏整个状态条并禁止交互，最后一层实际退场后恢复最新状态，计时不暂停。该方案已核对 unified_popups 2.2.1 的 pause / resume 与应用模态深度；不连续弹出多模式完成或恢复确认，回对应模式处理。
- 计时声音与触感只属于当前查看模式；离开所有计时页面后所有计时反馈静默，不合并或轮流播放多模式反馈。计圈面板仍允许其模式反馈；通用设置 / 编辑 / 确认层静默。切换停旧模式声音及待发触感，返回不补播；打卡、查看触感和显式试听保持各自规则。
- 统计延续各模式已入账记录分别累加，重叠不去重。三模式各记录 10 分钟合计 30 分钟，不新增运行区间事实。
- 后台提醒默认关闭；关闭时取消计时和习惯的全部系统 pending，保留 delivered，不关闭前台站内展示。范围包含番茄专注、正计时 59:59、倒计时及短休 / 长休完成。
- Android 计时支持精确闹钟授权，拒绝降级并说明可能延迟，习惯非精确；通知权限和精确权限分开表达。
- 每习惯每天最多一次，每周目标达成仍按当日未打卡提醒；过时不补发，已消耗当天机会后不因编辑再提醒。打卡取消，撤销 / 取消仅在时刻未到且机会未消耗时重排。
- 后台声音沿用总开关和来源局部偏好，触感由系统 / Android 渠道管理，不承诺复刻前台双强震；不受当前查看模式限制。
- iOS 使用逐习惯有界预约，明确显示实际覆盖范围，不改为每日汇总；预留三模式计时容量，不能承诺长期不打开时无限期逐习惯提醒。
- 最终回查 R1 已确认：习惯提醒到点且应用前台时，习惯提醒开启、当天未完成并满足每日一次规则，则显示约 3 秒静默短提示，点击定位习惯；模态期间跳过不补发，不加声触、不占计时三行，同一次到点不再后台重复提醒。前台仅受习惯自身开关控制，不依赖后台总开关或系统权限；后台另受后台总开关、权限及实际预约控制。
- 第六阶段 R2 已确认：中 / 大专注 Widget 和一张汇总实时活动最多展示三个模式，包含正计时和番茄休息，暂停保留；小尺寸 / 动态岛紧凑态优先运行中距到点最近者，同时间按番茄 → 正计时 → 倒计时，无运行态时按固定顺序选暂停态。
- 第六阶段 R3 已确认：外部内容点击回对应页面，额外最多暂停 / 继续，不提供开始 / 结束 / 放弃 / 打卡；仅在平台能安全进入统一业务命令时直接执行，否则打开应用完成该意图。某模式完成不能提前结束其它模式仍运行 / 暂停的汇总活动。
- 不兼容或迁移旧数据，直接采用新三模式格式；用户自行卸载旧包或手动清理缓存，应用不静默自动清空不支持数据。
- 优先第五阶段；第六阶段布局 / 原生配置可独立准备，三模式事实、公开投影和身份命令稳定后即可接入，不必等待第五阶段整体验收。两阶段消费同一份事实与命令，不各造计时器。
- 由 Agent 自主安排合理验证，不频繁测试或启动模拟器。声音与震动由用户在 Android / iOS 真机最终验收。交付临时验收脚本及步骤，用户通过后清理临时材料，必要长期回归保留；最终规则同步产品与工程文档。

第五阶段 D1–D10 已完成确认，不再重复询问。原建议的多模式声音合并和跨根 Tab 计时反馈已被当前模式门控替代。

最终回查 R1–R3 已全部确认，不再作为待决项。本次不改变既有时长上限、短记录确认、番茄轮次、计圈或冷进程恢复暂停规则。第六阶段系统刷新为尽力更新，不能承诺每分钟准时；异常终止时旧活动可能暂时继续展示，重开后同步恢复暂停，不用补写历史掩盖系统边界。具体平台 API、签名、刷新能力和设备覆盖在工程接入时核对，产品组合以已确认规则为准。
